# Generating media

The connector renders; the workspace keeps. An asset that stays at the vendor is not a deliverable — it is a link that will rot. Land it here, cited, or the act did not happen.

## Before generating

1. **Read the brief first.** Generation is the most expensive verb in the workspace and the least reversible in cost. Find the file that states what this is for; if there is none, write the brief before rendering anything.
2. **Name the one thing.** A clip carries a single message, like an image does. If you cannot say it in a sentence, you are not ready to spend the credits.
3. **Check what already exists.** Search the folder before rendering a second take of something already there.

## Steps

1. Generate ONE asset and look at it. Never fan out variants on a first pass — a wrong brief renders wrong four times.
2. Land it in the folder of the work it serves, never in a media dump. `derived_from` names the brief and any source image or script it was made from.
3. Say what it cost, in the member's terms, when the connector reports it.
4. Iterate by changing the brief, not by re-rolling the same prompt. A re-roll is a coin flip; an edited brief is a decision.

## Quality bar

- The asset sits beside its brief, and the provenance edge names it.
- The member can tell what was generated from what, months later, without asking.
- A refusal or a vendor failure is reported as itself — never a placeholder that composes as though it worked.

## Anti-patterns

Rendering before reading the brief. Four variants nobody asked for. Leaving the asset at the vendor and pasting a link. A prompt the member cannot find afterwards. Re-rolling to fix a brief. Treating a generated asset as a fact — it is an illustration, and it cites nothing on its own.
