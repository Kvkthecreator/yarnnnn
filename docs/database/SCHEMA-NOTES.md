## ADR-059: Simplified Context Model (Current Schema)

**Tables** (use these names, not legacy):
- `platform_connections` (not `user_integrations`). **ADR-635 (2026-09-03)**: an ATTACHED connector is a row keyed `platform = 'mcp:{slug}'` — `UNIQUE(user_id, platform)` satisfied by the prefix, no migration. `credentials_encrypted` holds ONE encrypted JSON envelope (access token, DCR client id/secret, token endpoint, expiry, resource; the PKCE verifier while `status='pending'`), `refresh_token_encrypted` the refresh token, `metadata` = `{server_url, title, name, category, auth, tools[], aperture{tool: direct|propose}, drift?}`. **am.1 (2026-09-18)**: `drift` = `{withdrawn[], appeared[], at}` — what the last `refresh_tools` found moved on the server. `tools[]` is a snapshot and the aperture is keyed on tool NAMES, so a rename silently revokes consent; this is that fact, written by `refresh_tools`, served by `public_view` + `GET /api/integrations`, and **cleared by `set_aperture`** (the member's save IS the acknowledgement). Absent when nothing moved — never an empty record. Read only through `platform_credentials.resolve_platform_credential`. The steward-era `watch_id`-set rows (ADR-335) are gone with `TrackForeign` (measured 0 in prod).
- `platform_content` — **DROPPED (ADR-153)**. Was unified content layer with retention (ADR-072). Platform data now flows through tasks into workspace context domains.
- `filesystem_documents` / `filesystem_chunks` — uploaded documents only
- `user_memory` — single Memory store (replaces knowledge_profile, knowledge_styles, knowledge_domains, knowledge_entries)
- **DROPPED (migration 248, 2026-08-26)** — `agents`, `agent_runs`, and six fossils (`agent_context_log`, `agent_export_preferences`, `agent_proposals`, `agent_role_metrics`, `agent_source_runs`, `agent_validation_results`), plus the columns `agent_type` / `agent_instructions` / `agent_memory` that hung off `agents`. They were ADR-109's Scope×Role×Trigger model: an agent as a per-workspace DB row. **ADR-596/600 replaced it — an agent is a BEING, a row in `services/agents_registry.AGENTS`, static kernel data.** All eight tables held ZERO rows in production and six had zero code references. The dangling FK columns on live tables went too (`chat_sessions.agent_id`, `execution_events.agent_run_id`, `export_log.agent_run_id`, `action_proposals.agent_slug` — each measured 100% NULL). Gate: `api/test_agent_model_is_retired.py`.
- `tasks` — **the ONE drain loop's index** (ADR-639 D3, re-founded on the ADR-231 D4 Path B thin index, migration 164; `kind` column — `standing` for standing work, the capture lane beside it). **`claimed_until timestamptz NOT NULL DEFAULT 'epoch'` (migration 258, ADR-659 D1)** is the run's LOCK: `claim_run` holds the row with one conditional update (`claimed_until < now()`), `record_run` releases it to epoch, and NOTHING else writes it — in particular no materializer. It replaced a sentinel parked in `next_run_at`, the column the materializer owns, which a tick could rewrite mid-run (driven 2026-09-20: a second claim succeeded while the first run was in flight). `NOT NULL DEFAULT 'epoch'` keeps the claim a single `lt` filter rather than an `or(is.null, lt)`. It is LIVE by code even when it reads 0 rows (no declaration indexed); ADR-632's "drop with wake_queue" no longer applies. Historical shape: Columns: `id, user_id, slug, status, schedule, next_run_at, last_run_at, created_at, updated_at, declaration_path, paused`. The `mode` and `essential` columns dropped. Authoritative recurrence-declaration substrate is workspace_files YAML at `declaration_path` (e.g., `/workspace/reports/{slug}/_spec.yaml` for DELIVERABLE shape). The table is fully reconstructable from filesystem state via `services.scheduling.materialize_scheduling_index()`. The table name "tasks" identifies the SCHEDULING INDEX, not work substrate. **`/tasks/{slug}/` filesystem tree DELETED per ADR-231 D2.** Per-shape natural-home paths per D2/D3: DELIVERABLE → `/workspace/reports/{slug}/_spec.yaml` + `/workspace/reports/{slug}/{date}/output.md`; ACCUMULATION → entry in `/workspace/context/{domain}/_recurring.yaml`; ACTION → `/workspace/operations/{slug}/_action.yaml`; MAINTENANCE → entry in `/workspace/_shared/back-office.yaml` + audit log at `/workspace/_shared/back-office-audit.md`.
- `workspace_files` — virtual filesystem for agent workspaces (ADR-106); path-based access, full-text + vector search; `content_url` column for rendered binary files (ADR-118). ADR-118 Phase D: becomes the single output substrate for all agent outputs (text + binary), replacing agent_runs as the delivery source. ADR-119: adds `version` + `lifecycle` columns; folder conventions (output folders with `manifest.json`, project folders, ephemeral `/working/`) replace relational grouping tables. **ADR-209 (2026-04-23)**: adds `head_version_id` pointer column + two sibling tables for the Authored Substrate: `workspace_blobs` (content-addressed CAS keyed by sha256) and `workspace_file_versions` (parent-pointered revision chain with required `authored_by` + `message` attribution). `ADR-119 Phase 3 /history/` subfolder convention superseded — versioning moves from filesystem namespace to substrate-native revision chain. `version` integer column scheduled for drop in ADR-209 Phase 5.
- `workspace_blobs` — ADR-209 Authored Substrate: content-addressed immutable store keyed by sha256. Shared across workspaces (identical content reuses one blob). No user-level scoping — scoping lives at the revision layer.
- `workspace_file_versions` — ADR-209 Authored Substrate: parent-pointered revision chain per `(workspace_id, path)` (ADR-373 Phase 1 Implemented — the workspace is the binding unit via `authored_substrate.py::_substrate_scope`; `(user_id, path)` is the N=1 fallback). Every mutation to `workspace_files` produces exactly one row here. `authored_by` taxonomy: `operator` | `yarnnn:<model>` | `agent:<slug>` | `specialist:<role>` | `freddie:<identity>` (the live prefix since the 2026-06-29 full rename; legacy rows carry `reviewer:<identity>`) | `member:{user_id} via {model}` (ADR-408 D2 · ADR-460 lane writes) | `system:<actor>`. `parent_version_id` is NULL on the first revision for a path; forms a walkable DAG. **`revision_kind` column (ADR-423, migration 208, Implemented 2026-07-08):** `authored` (default — an ordinary revision; all pre-migration rows read this, no backfill) | `observation` (a retained raw intake — the 3 intake writers [MCP `remember`, connector capture via `_write_if_changed`, `TrackWebSources` raw write] tag it) | `derivation` (a derived act citing its sources — first live writer: the ADR-395 upload projection, per ADR-448; the MCP-remember derive step is still prompt-only). This is what lets the `inbound/` directory dissolve — a raw arrival is marked by its `revision_kind`, not its path, so the two raw lanes unify under one operator-facing **Downloads** zone (the Files-model note, `docs/analysis/the-files-model-directory-is-meaning-everything-else-is-metadata-2026-07-08.md`). `write_revision(revision_kind=...)` threads it; only written when non-default (byte-identical authored writes). **`derived_from` column (ADR-448, migration 215, Implemented 2026-07-12):** JSONB list of absolute workspace paths — the REFERENCE EDGE (what this revision was made from). Written when a caller passes `derived_from=` (a declared derive act → kind defaults to `derivation`) or LIFTED at the write door from the two content conventions (head-anchored `derived_from:` frontmatter → edge + kind; artifact `data-ref` citations in `.html` → edge only). Readers: `list_revisions`/`read_revision`/`trace` (column-first, content-scan legacy fallback) + `authored_substrate.list_dependents` (which HEADs cite a path — serves `GET /api/workspace/file/dependents` + the Files delete-confirm "N files were made from this" warning). Edges are historical facts, never live FKs (a move doesn't rewrite the ledger). This is the load-bearing-files axiom made structural: importance is a GRAPH position (legibility=edges, protection=powerbox grants, version-coupling=data-ref pins), never a folder class — see the load-bearing-files note + [ADR-448](../adr/ADR-448-the-reference-edge-derived-from-on-the-ledger.md). **ADR-373 (Phase 1 Implemented — corrected 2026-07-09, was mislabeled "not yet Implemented"):** the substrate's binding unit moves from `(user_id, path)` to `(workspace_id, path)` — `workspaces` table + a `workspace_id` FK; `user_id` relocates to a `principal_grants` membership/authorization fact. The 1:1 world is the N=1 case (backfill: each `user_id` → a singleton owner-workspace, byte-identical behavior). The workspace becomes a **multi-principal** attributed commons (humans, their agents, other humans, platforms, foreign/local LLMs each attribute as themselves); per-principal grant reinterprets `CALLER_WRITE_POLICY` as class-defaults; single-writer-per-path (ADR-286) means **no merge/CRDT layer** — semantic conflict is reconciled by the workspace-level Reviewer seat. **Migrations `189_adr373` (principal_grants + workspace_id FK + N=1 backfill) / `198_adr373` (member write-scope) / `199_adr404` (invites) are in-tree; `_substrate_scope` keys the chain on `workspace_id`.** Additive-remaining: richer member-provisioning UX. See [ADR-373](../adr/ADR-373-multi-principal-workspace-and-the-re-key.md).
- **`pgroonga` extension + `search_workspace`'s Korean tier — migration 260 (2026-09-21), APPLIED.** `search_workspace` matched with `to_tsvector('english', …)`, which whitespace-splits Korean and stems nothing. Korean is agglutinative — a particle welds to its noun — so a noun was found only when it appeared BARE, the minority case in real prose. Measured on production against a Korean file a member had already authored (`operation/한국어-커넥터-테스트.md`, whose own item 3 asks "can I find this file again with a Korean query"): `커넥터` 2 · `한국어` 1 · `테스트` 1 (bare: found), but **`본문` 0 and `삭제` 0** (they appear only as `본문이` / `삭제하거나`), against an English control of 20. It never errored; it returned fewer rows, which reads as "search is bad", not "search is broken". Postgres ships **no** Korean text-search config (all 29 enumerated, no CJK), and `simple` does not help — it skips stemming but the particle still welds. The semantic fallback is not a net either: 8 of 902 rows carry an embedding. **`pgroonga` is ADDED, never substituted**: it substring-matches (finding a noun inside an inflected word) but does NOT stem, so alone it REGRESSES English — measured, `reports` 185 → 106 because it stops matching `report`. The hybrid beats both (`reports` 191, `workspace` 423). It joins 246's ladder as a **third tier below strict and loose**, firing only on a double miss, so every English query returns byte-identical rows to before — verified. `match_mode` gains the value **`korean`**, and `primitives/workspace.py` grades it WEAK alongside `loose`: a substring hit reported as precise would be the inverse of the 2026-08-22 false-miss defect the ladder exists to prevent. Indexes `workspace_files_content_pgroonga` + `workspace_files_path_pgroonga`. **Cost, measured:** builds in <3s on the live table; database 307 MB → 397 MB, ~90 MB of index for ~8.6 MB of content. ⚠️`pg_relation_size` reads **0** for a pgroonga index (it stores outside the Postgres relation) — measure by `pg_database_size` delta or you will report 90 MB as free. Gate: `api/test_search_speaks_korean.py` 20/20 **against the live database**, falsified both ways (reverting the grader reds 1; restoring the pre-260 function reds 3 by reproducing the original 0-hit defect).
- **`workspace_files.path` / `workspace_file_versions.path` are NFC — migration 259 (2026-09-21), APPLIED.** A non-Latin name has two byte forms that render identically: a Hangul syllable is one composed character (NFC) or several combining jamo (NFD), and nothing compares them equal — not Python, not Postgres (`'한글' = normalize('한글', NFD)` is false; `length` 2 vs 6), not git. macOS decomposes filenames, so a Korean file uploaded from Finder landed NFD while the same name typed in the browser landed NFC. Measured before the fix: of four Hangul paths, **two were NFC (authored in-app) and two NFD (uploaded)**, and each was findable ONLY in its stored form. Since `path` is the substrate's binding unit (ADR-373), the single-writer unit (ADR-286) and the revision-chain key (ADR-209), two spellings of one name were two identities and two revision chains. ⭐The origin was `services/documents.py::_filename_to_slug` using `[^\w-]` with `re.UNICODE` — **Python's `\w` matches Hangul**, so the OS's form passed into `path` verbatim. The doors that MINT a path now fold to NFC (`services/naming.py::nfc`, applied at the upload slug and at `parse_file_reference`, with the TS twin in `web/lib/interop/fileHandle.ts`); reads are deliberately NOT normalized, which would have orphaned the legacy rows by their own stored spelling. 259 moved both tables together (6 version rows, 2 file rows) so a head never points at a spelling its history lacks, with a collision guard that ABORTS rather than merging two files onto one key. **Post-migration receipt (verify the LIVE object):** 0 non-NFC rows in both tables, all 4 Hangul paths intact, every Hangul head path matches a version-chain row, and the two previously-unfindable files now resolve by their composed name. Gate: `api/test_nfc_one_unicode_spelling.py` 17/17.
