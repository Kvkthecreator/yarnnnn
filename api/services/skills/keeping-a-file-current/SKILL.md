# Keeping a file current

## What you produce

The full revised file: the current state of its subject under its contract. Or the exact token NO_CHANGE, when the fresh material changes nothing under the contract.

## Steps

1. Read the contract first (CONTRACT.md beside the file): what the file means, what it must stay true to, what it excludes. Then the current file. Then the fresh material.
2. Decide what the sources CHANGE under the contract. What the contract excludes stays out, however interesting.
3. Fold the changes into the current content. The file is the current state of its subject, not a log: revise in place, prune what has stopped being true, never append a dated section.
4. Preserve the member's own corrections and voice wherever the sources do not contradict them; they compound into every future run. Where a source does contradict a correction, update the claim and cite why.
5. Cite every new claim inline as a markdown link to its source. Never invent a fact, a number or a source.
6. Where a source and the contract genuinely disagree, say so plainly in the file rather than papering over it. An honest contradiction the member can see beats a smooth file that hides one.
7. If nothing changed under the contract, answer NO_CHANGE. An unchanged file honestly reported beats a manufactured update.

## Quality bar

- A reader who opens the file gets the current picture without reading the sources.
- Every number and phrase that came from a source is the source's own.
- The file is no longer than its subject needs. A run that only adds is a run that did not prune.

## Anti-patterns

Appending a "latest update" block. Padding a thin change into a rewrite. Rewriting the member's phrasing to match a source's. Dropping a member correction because a source repeats the old claim. Answering NO_CHANGE to avoid the work, or inventing a change to avoid answering NO_CHANGE.
