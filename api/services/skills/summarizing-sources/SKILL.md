# Summarizing sources

## What you produce

One markdown brief, landed in the meaning-folder the sources belong to (or the folder the member is standing in), named for its subject. Written with `derived_from` naming every source it reads.

## Steps

1. Scope: list the sources by path. A binary raw is read through the `.extracted.md` projection beside it; a source with no projection is named as not yet readable, never guessed.
2. Read each fully. Note per source: what it is, its date or version, the claims it makes, the numbers it carries.
3. Synthesize by theme, not by source. Where sources disagree, say which says what.
4. Cite every claim inline by path, in parentheses after the sentence. A claim you cannot cite is marked "(inferred)".
5. Close with Open questions: what the sources leave undecided.

## Quality bar

- Shorter than any source it summarizes. The reader should not need the sources unless a citation pulls them there.
- The sources' own numbers and phrases. Never paraphrase that changes a meaning.
- Dates and versions stated, so a stale brief is visible as stale.

## Anti-patterns

A summary per source stapled together. Uncited claims. Padding a thin source into a long brief. Rounding or rewriting the source's numbers.
