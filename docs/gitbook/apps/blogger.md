# Blogger

Blogger is where you write for someone **outside** the workspace — a post, an essay, a landing page. Everything else you write is for you and your team; this is the one surface whose reader is a stranger.

Name a post, then say what you want in plain words. It takes shape section by section, using your files, images, and data.

If you're writing an internal document, that's [Text](text.md). If you're building something to present, that's [Slides](slides.md).

## The grammar of a post

A post is **banded**, not staged. You stack full-width sections — a header, prose, a feature grid, a call to action — and each band centres its content in a reading column. There's no positioning: a post has a viewport, not a frame, so the bands reflow to any width. That's the difference from a deck, and it's the right one for something read on a phone as often as a laptop.

Containers are real, selectable structure: click a band to select it, press **Esc** to walk up the chain (block → band → post), and use the layout controls — padding, alignment, width — on whatever you have selected.

## Arrangements

Layout presets that place content for you:

**Article header** · **Prose** · **Hero** · **Content** · **Feature grid** · **Testimonial** · **Call to action** · **Footer**

The long-form pair — *Article header* then *Prose* — is what opens a blog post or essay: a kicker, title, standfirst and byline, then a narrow reading column for the body.

You can also ask the lane to **re-arrange** an existing post: it plans where each band belongs, and the mechanism places them.

## Blocks

The same vocabulary as the rest of the workspace:

Heading · Text · Callout · Quote · Bulleted list · Numbered list · Checklist · Divider · Toggle · Button · Component · Table · Metrics · Chart · Figure · Gallery

A Chart is drawn from a CSV in your workspace, live — when the data file changes, the chart follows. Figures and galleries cite real workspace files rather than pasting copies, so a post made from your substrate stays connected to it.

## The bound lane

The right-hand column is a chat lane bound to the post you have open, and the agent beside you is **Blogger** — its own resident, not the one you meet in Text and Slides.

That's deliberate. [Editor](agents.md) writes *your* document in *your* voice. Blogger writes for a reader who has never seen your workspace, doesn't know your shorthand, and needs the context spelled out. Those two postures conflict inside one character, so they're two agents.

Both hands write to the same file — you directly, and the lane when you ask — and both land as attributed revisions.

## Publishing

A post is a file in your workspace like any other until you send it somewhere. Publishing to WordPress runs through [Reach](reach.md), which is where anything leaving the workspace surfaces before it goes.

## File operations

The open post carries the standard verbs: rename, move, duplicate, copy link, move to trash. They behave identically to the same verbs on the [Files](files.md) surface.
