## Purpose

This document defines the foundational axioms of YARNNN's cognitive architecture. It is not an implementation guide — it is the conceptual substrate from which implementation decisions follow. Everything in `docs/adr/`, `docs/architecture/`, and the codebase should be derivable from or consistent with these axioms.

## Scope: This Document Describes the System, Not the Surface That Iterates On It

FOUNDATIONS describes **YARNNN itself** — the Agent OS. The entities named here (agents, members and their lanes, standing declarations, apps, the substrate, primitives, grants, gates) are *inside the system*. The real operator's interface to YARNNN is the desktop of surfaces and the chat lane; everything that drives execution and gating lives in-system.

The **developer surface that iterates on YARNNN** — including the human author of these docs, Claude as a collaborator, the operator-proxy capability (ADR-294), scripted scenario runners, observation captures, ADR drafts, regression gates — is **outside the system**. It is the toolchain through which YARNNN's canon evolves. It is NOT part of the system's runtime architecture and does not appear as an actor in any axiom below.

When reading FOUNDATIONS: every "agent," "member," "operator," and "substrate" reference is a system-side entity. When you see "developer" or "Claude" or "operator-proxy" or "observation discipline," that's tooling outside this canon — those concepts belong in `docs/evaluations/README.md` (the developer-evaluation discipline doc), not here.

The aspiration is that YARNNN becomes a fully autonomous Agent OS where the agents a workspace's members work with reason, act, edit substrate and learn on their own initiative — all under in-system discipline, audit trail and revertibility, with authority held on grants, declarations and gates rather than on the agent (ADR-596). Today's lock-set — the grant sidecars in each agent's home (ADR-624) — is **current dev-trust state**, not a permanent architectural line; as the gates harden, the lock-set shrinks toward zero.

This scope distinction is load-bearing: it means findings from developer-side evaluation runs feed into amendments of in-system canon (FOUNDATIONS, ADRs, persona frames, principles bundles) but **do not introduce new architectural concepts that only the developer can see**. Every system property must be expressible from inside the system. The developer surface is an accelerator of YARNNN's evolution, not a co-resident of YARNNN's runtime.

## Axiom 0: Six Dimensions, Not Phases

Every mechanic in YARNNN — every table, every file, every service, every prompt, every surface, every ADR — occupies a cell in **six orthogonal dimensions**. The dimensions are the irreducible questions the system must answer:

| Interrogative | Dimension | What it decides |
|---|---|---|
| **What** | **Substrate** | What persists; what is true between invocations |
| **Who** | **Identity** | Which cognitive layer acts; which identity authors or consumes |
| **Why** | **Purpose** | What intent drives the work; what the objective is |
| **When** | **Trigger** | What invokes execution — reactive (substrate-driven) or addressed |
| **How** | **Mechanism** | By what means the work happens — a spectrum from deterministic code to LLM judgment |
| **Where** | **Channel** | To what location or surface output is addressed |

The six are **dimensions, not phases.** A cron firing is not "in the Trigger stage"; it is *one cell's position along the Trigger dimension*. The same invocation simultaneously occupies cells in Substrate (what it reads/writes), Identity (who is running), Purpose (why this fires now), Mechanism (how the work is done), and Channel (where output lands). Design errors happen when a mechanic is allowed to span a dimension without necessity — conflating Substrate with Identity, or Purpose with Channel, or Mechanism with Trigger.

### The three pairings (mental mnemonic)

As a cognitive aid, the six pair into three natural couplings:

- **Substrate ⟷ Identity** — *what is*, *authored by whom*. Every file has an author; every domain has a reader.
- **Purpose ⟷ Trigger** — *why*, *when*. Intent drives invocation. Trigger without purpose is noise; purpose without trigger is dormant.
- **Mechanism ⟷ Channel** — *how*, *where*. Means produces a targeted artifact. Rendering is Mechanism; addressing the surface is Channel.

The pairings are how humans think about the system. The dimensions are what the system must separately decide. Both frames are useful; they are not the same.

### Why this axiom now

The architecture grew a vocabulary faster than it acquired discipline for that vocabulary. By 2026-04 the repo had dozens of named mechanics — primitives, tool profiles, scheduling, pulse (deleted), proactive review (deleted), compose substrate, the review seat (since deleted), feedback actuation, back-office tasks, MCP surface, surface archetypes, inference hardening, impersonation, outcome reconciliation — each designed, each defended, each ADR-ed. Many were correct. Some were cross-cuts that confused one dimension for another. Without a dimensional test, the mistakes were only caught retroactively (Composer → YARNNN, pulse → dissolved, project layer → collapsed, platform_content → sunset, action_outcomes SQL → filesystem).

Axiom 0 is the architectural conscience that catches these conflations *before* shipped code accretes dependents. The previous Axiom 0 (v5.1, filesystem-is-substrate) is preserved — it is now Axiom 1 below, the Substrate dimension stated axiomatically.

### Test for new features

Before adding a mechanic, answer the six:

1. **What** does it read/write? (Substrate cell)
2. **Who** authors/consumes it? (Identity cell)
3. **Why** does it exist — what intent is served? (Purpose cell)
4. **When** does it fire — reactive (substrate-driven) or addressed? (Trigger cell)
5. **How** does it work — code, LLM, or a blend? (Mechanism cell)
6. **Where** does its output go? (Channel cell)

If two questions have the same answer, the mechanic is conflating dimensions — redesign. If one question has no answer, the mechanic is incomplete — specify before shipping.

## Axiom 1: Substrate — Filesystem Is the Persistence Layer

**What persists lives in files. Nothing else persists.**

YARNNN's semantic state lives in the filesystem (`workspace_files` today; storage-agnostic by design per ADR-106). Every other architectural layer — scheduling, reasoning, review, reconciliation, rendering, delivery — is **stateless computation** that operates *over* the filesystem. State lives in files. Components do not hold state; they read files, act, write files, and terminate.

This axiom was introduced in v5.1 (previously Axiom 0). Its content is preserved; only its number changed. It remains the single most load-bearing architectural property: every prior collapse of a parallel substrate happened because semantic content was placed in a DB row when it belonged in a file.

### What this means concretely

- **Semantic content lives in files.** Entities, theses, observations, track records, feedback, decisions, identities, charters — all filesystem. A DB row that holds semantic content is, by default, a violation.
- **Computation is stateless.** The scheduler holds no work-definition state; it reads the standing declaration (`_standing.yaml` + `CONTRACT.md`). A lane holds no output state; it writes revisions. Every component reads the filesystem, acts, writes the filesystem, and terminates. State persists only in files.
- **Accumulation happens in files across invocations.** Each cycle adds to context. The recursive property (Axiom 7 below) is enabled by the filesystem being the single accumulation target.
- **Mechanism varies; statelessness does not.** Scheduling is periodic (cron); execution is one-shot per invocation (task pipeline); review is reactive (triggered by proposal creation); reconciliation is periodic (daily back-office task); rendering is invocation-scoped (compose engine). Different shapes of Mechanism, one invariant: none retain state of their own.

### Four permitted kinds of database rows

DB rows are not banned — they are narrowly permitted. Every table in the schema must fall into one of four categories:

1. **Scheduling indexes** — what needs to run, when. Examples: `tasks` (schedule + mode + next_run_at), `agents` (identity pointer + role). These are lean pointers at files; the file is the source of truth.
2. **Neutral audit ledgers** — what happened, for billing / debugging / forensics. Examples: `execution_events`, `token_usage`, `activity_log`. No semantic content. (`render_usage` dropped with the render service, ADR-417; `agent_runs` dropped with the pre-ADR-596 agent model, migration 248.)
3. **Credentials / auth** — encrypted secrets the filesystem cannot hold safely. Examples: `platform_connections`, `mcp_oauth_*`. Opaque to everything except the decryption path.
4. **Ephemeral queues / inboxes** — pending items with hard TTLs awaiting action, not accumulating. Example: `action_proposals` (proposed writes, TTL-bounded, swept by back-office cleanup). The row disappears after acceptance, rejection, or expiration.

Anything that doesn't fit one of these four patterns belongs in the filesystem.

### Secondary benefits of filesystem-first discipline

- **Storage-agnostic** — Postgres today, cloud storage later, no code change (ADR-106).
- **User-legible** — operators can read their own accumulated context. Tables are opaque; markdown is transparent.
- **Agent-legible** — every agent reads files natively. No ORM, no schema coupling.
- **Version-history-native** — every write is attributed and retained in-substrate; no sibling audit store (see "Every write is attributed and retained" below, and `authored-substrate.md`).
- **Model-agnostic** — files are the universal interface across LLM providers and interoperability protocols (MCP).

### Corollary: Substrate grows from work, not from signup scaffolding (ADR-205)

The filesystem-first commitment is not only about *where* state lives — it is also about *when* state comes into being. Substrate should materialize through user action (tasks writing, conversations resolving, uploads landing), not through framework-level pre-creation at signup. A fresh workspace is textually present (identity, brand, uploads) and structurally empty (zero user-authored Agents, zero context domain directories, zero user-authored tasks beyond the deterministic daily-update heartbeat and back-office tasks). Directory registries exist as *naming conventions* consulted at first-write, not as *pre-creation manifests* run at signup.

This corollary strengthens Axiom 1 rather than extending it: if the substrate is where state lives, then populating the substrate before work exists is itself a Substrate violation. It places content in the persistence layer ahead of the purpose that would justify it.

### Every write is attributed and retained (Authored Substrate — ADR-209)

Axiom 1's first clause says *where* state lives (the filesystem). This second clause says *how* state evolves: **every mutation to the substrate is attributed, purposeful, and retained.** No write is anonymous; no prior state is silently lost.

Three sub-properties, enforced at the substrate layer (not by convention, not by sibling audit tables):

1. **Content-addressed retention.** Every revision of every file is stored immutably. The current state is a pointer at a `head` revision; every prior revision remains queryable. Overwrites are never destructive — they add a revision.
2. **Parent-pointered history.** Each revision records the revision it descended from. The revision chain for any path is walkable backward — diff, revert, and history traversal are substrate operations, not application features layered on top.
3. **Authored-by attribution.** Every revision carries an author identity (a member, an agent, a connected principal, or a named `system:` actor) and a short message. Writes without attribution are rejected at the write-path boundary.

This is the substrate-level enforcement of Axiom 2 (Identity). Axiom 2 says *"every file has an author"*; Axiom 1's Authored Substrate clause makes that enforceable rather than aspirational. It is also what makes Axiom 7 (Recursion) legible at fine grain: the recursive accumulation loop becomes auditable revision-by-revision, not just file-by-file.

The architecture is canonically named **Authored Substrate**. The naming deliberately avoids "git" — YARNNN adopts three of git's five core capabilities (content-addressed immutability, parent-pointer history, authored attribution) without inheriting the other two (branching, distributed replication) or git's implementation. See [authored-substrate.md](authored-substrate.md) for the full design, the git-inspiration framing, and what is deliberately deferred.

This clause supersedes the `/history/` subfolder convention that ADR-119 Phase 3 introduced as an interim versioning approach. Filename-encoded versioning (`thesis-v2.md`, `-archive` suffixes, per-file `/history/v{N}.md` subfolders) is also retired — versioning lives in a separate metadata plane, never in the namespace. See ADR-209 for the full deprecation manifest.

### External-system state lives in substrate too (ADR-264)

Axiom 1's first clause says *where* state lives (the filesystem). The Authored Substrate clause says *how* state evolves (every revision attributed and retained). This third clause says **what kinds of state belong**: every piece of state an agent reasons about lives in the substrate, regardless of whether it originates internally or externally.

External-system state — broker positions, order fills, account balances, commerce revenue, customer churn signals, news arrivals, GitHub release shipments, Slack channel activity — reaches the substrate through the intake pipeline (`retain → distil → signal → read`, [intake-pipeline.md](intake-pipeline.md)): a capture lands an attributed observation at the fixed intake lane, a derive step distils it, and judgment reads the distillate. Turn reach (ADR-615) — a tool call inside one member's turn, under the member's own connection — is transient and is the one exception this clause admits: it dies with the turn and never becomes the substrate's model of the world by itself.

The principle: **the workspace's substrate is the workspace's complete model of the world, including state that originates in external systems.** Judgment reads substrate. It does not call external APIs as primary perception; a live read inside a turn (ADR-615) is a convenience for the member's question, not the record.

Platform tools (`api/services/platform_tools.py`) survive as turn-time conveniences for ad-hoc lookups not yet captured, reached only under the acting member's own connection (ADR-577/615). When a piece of external state is referenced often, the member connects the platform and its captures land in the intake lane; judgment reads the distillate.

This clause closes the substrate-as-canonical-model loop: with this in place, an agent's perception is uniformly substrate-driven. Internal declarations + external mirrored state + accumulated narrative + outcome reconciliation are all substrate; the agent reads files and reasons against them; no parallel perception layer exists.

### Substrate is the bus the runtime Loop runs over (hardening, 2026-05-11)

The first three sub-clauses say *where state lives*, *how it evolves*, and *what kinds belong*. This fourth sub-clause says **how the runtime relates to substrate**: substrate is not a side-effect of running the system — substrate IS the bus over which the runtime operates.

The lane runs *over* substrate, not *alongside* it. A turn reads substrate, acts through primitives, writes revisions; the next turn — attended, or a standing declaration's run — reads what the last one wrote. There is no parallel control-flow channel between turns: the substrate revision (with its `authored_by`) *is* the message.

Standing work and capture — the scheduler's lanes (ADR-639, ADR-582) — are the deterministic end of the same architecture. They run *between* attended turns, keeping substrate current so a lane has truth to read when it next runs. They write substrate; the lane reads substrate; same bus, same medium, no parallel mediation layer.

The principle: **the Loop sleeps; substrate persists; the Loop wakes, reads substrate, acts via substrate writes, sleeps again.** This is what makes "the operating entity continues to operate while the human supervisor is absent" structurally true rather than aspirational. The operating entity's continuity lives in the substrate, not in any running process. There is nothing to lose when the Loop sleeps because the substrate is the entity's memory and its medium.

This sub-clause hardens what the prior three already imply: substrate is not the place the runtime *stores its outputs*; substrate is the place the runtime *exists*. Implementation collisions with this sub-clause — e.g., turn-to-turn direct return values, in-memory caches that bypass substrate writes, parallel control planes — are Axiom 1 violations.

### Substrate organization is operator-readable canon (ADR-281, 2026-05-15)

The four prior sub-clauses say *where* state lives, *how* it evolves, *what kinds* belong, and *what role* substrate plays in the runtime. This fifth sub-clause says **how the substrate is taught**: the substrate's organization is itself operator-readable canon, not kernel-internal knowledge.

Bundles ship a **workspace guide** (`docs/programs/{slug}/reference-workspace/_workspace_guide.md`) — the library's operating manual. Forked into the operator's workspace at activation. An agent reads it in its frame; the operator can edit it. The frontmatter is machine-parseable (mirrors the bundle MANIFEST's `substrate_abi` declarations); the prose body teaches the five-role taxonomy (`operator-canon` / `system-ledger` / `world-mirror` / `running-narrative` / `kernel-index`), what NOT to write to operator-canon, and what to do when substrate diverges from declaration.

**The kernel does not author its own pedagogy.** Substrate semantics are bundle-shipped operator-canon, not Python-string-injected at prompt assembly. This sharpens the kernel/program boundary (Principle 16) at the substrate-pedagogy layer: kernels teach syscalls (the substrate-access ABI); bundles teach substrate organization (the workspace guide).

**Singular pedagogy surface.** Per ADR-277's rule of thumb applied at the substrate-pedagogy layer: each substrate concept has one canonical teaching surface. Persona prose, kernel constants, scattered docstrings — none of these are second canonical teaching surfaces; they are pointers at most.

See [ADR-281](../adr/ADR-281-substrate-canonical-substrate-only-prompts.md) for the derivation chain and [GLOSSARY.md](GLOSSARY.md) for the canonical role-taxonomy vocabulary.

### Single-writer per path (ADR-286, 2026-05-17)

The five prior sub-clauses say *where* state lives, *how* it evolves, *what kinds* belong, *what role* substrate plays in the runtime, and *how* the substrate is taught. This sixth sub-clause says **who writes each path**: every substrate path has exactly one authoritative writer.

The discipline rule mechanically separates the writers:

- **Kernel-universal paths** — present in every workspace regardless of program activation. Written by `services/workspace_init.py` Phase 2 at signup. Examples: `context/_shared/PRECEDENT.md`, `memory/_playbook.md`, `review/calibration.md`, `review/OCCUPANT.md` (kernel scaffold; ADR-284 Phase 1 helper overwrites at bundle-fork with runtime occupant), `review/handoffs.md`.
- **Bundle-owned paths** — every path any active bundle ships via `reference-workspace/`. Written by `services/programs.py::fork_reference_workspace` at program activation. Examples: `context/_shared/{MANDATE, IDENTITY, BRAND, AUTONOMY}.md`, `review/IDENTITY.md`, `review/principles.md`, `_recurrences.yaml`, `_workspace_guide.md` (when program activated; kernel default only on no-program workspaces).
- **Member/agent/system paths** — written at runtime via the Authored Substrate pipeline (ADR-209) with the appropriate `authored_by` attribution. Examples: operator-authored edits to bundle-owned files; an agent's `memory/` notes (ADR-624); mechanical primitives writing world-mirror state.

The rule is verifiable mechanically: walk every active bundle's `reference-workspace/`; any path that appears in any bundle is bundle-owned and the kernel does NOT scaffold it.

**Amendment — single-*head*, many-*authors*, for the work-commons (the re-founding, 2026-06-29, REV-1).** The original rule (one authoritative *writer* per path) is the **single-principal** form and stays exactly as stated for **kernel-universal, bundle-owned, and `system/` paths** (machine-written, one writer by construction). For the **work-commons** (operator-meaning folders many principals co-write — ADR-373), the rule relaxes to **single current-state, many attributed revisions**: single-*head*-per-path is preserved (ADR-209 content-addressed CAS ordering — no two commits share a parent), while single-*author*-per-path is released, so a human, an external agent, and an agent in a lane can all author revisions of the one meaning-file. **This is conditioned on the single-substrate topology** (ADR-378 makes the workspace the outermost unit; federation is the deferred axis — under federated replicas with no shared head, concurrent cross-replica writes re-open CAS-sufficiency and this relaxation must be revisited). The chain serializes the **mechanics** (no CRDT/OT/merge code), but it does **not** resolve **semantics**: a genuine same-path contradiction (principal A writes "DynamoDB," principal B's next revision writes "Postgres") **relocates the merge into a judgment act** — a member, or an agent in their lane, authors the next head revision of the contested path itself, not a side-file. The merge does not vanish; it becomes judgment. **This couples to the ninth sub-clause**: folding raw intake into the meaning-file's chain (below) *manufactures* the same-path multi-principal write that ADR-373 D5 closed "by construction" — so this sub-clause no longer leans on that closure; it owns the in-band reconciliation. **Honest substrate state (2026-06-29):** the live workspaces are all N=1 (one principal each), so today's same-path co-writes are *cooperative same-principal* (the operator's two embodiments + system actors); the *competing independent-principal* same-path case is untested in substrate and is a runtime question for the implementation phase. See [the re-founding keystone](../analysis/the-re-founding-meaning-folders-and-permission-as-metadata-2026-06-29.md) §7.1 + the triple-check findings (analysis note, since removed) Attack A.

**Why this matters.** Pre-ADR-286 the kernel scaffold wrote defaults for 10 paths that the alpha-trader bundle also shipped. Two writers raced on those paths; reconciliation depended on a heuristic (`is_skeleton_content` trying to distinguish "kernel default that should be overwritten" from "operator-customized content that should be preserved"). The heuristic required a new patch per kernel-default content shape (placeholder phrases, principles signature, workspace-guide signature, short-and-sparse rule). Three substrate-drift incidents in five days traced to the dual-write pattern. ADR-286 eliminates the dual-write at the structural level; the rescue heuristics become unnecessary; the system gets smaller and more predictable.

**No-program workspace semantic.** A workspace at signup with no program activation has kernel-universal paths populated but bundle-owned paths absent. The lane frame renders empty-state hints for absent files. The workspace IS unconfigured — the envelope reflects that honestly rather than papering it with generic defaults that pretend a persona exists.

See [ADR-286](../adr/ADR-286-kernel-program-substrate-single-writer.md) for the full derivation, deletion ledger, and migration mechanism.

### The filesystem topology IS the permission policy (ADR-320, 2026-06-05)

The sixth sub-clause says *who writes each path* (single-writer). This seventh sub-clause says **how write-permission is derived**: from the path's top-level root alone, for every caller class, with no file enumeration. The workspace root is partitioned into **six semantic-class roots** — `governance/` (the GRANT — authority + spend — an agent runs under but cannot set), `contract/` (the operating contract — operator-declared deliverable preferences + output contract — the seat may revise against ground truth, mode-governed not locked — ADR-366), `constitution/` (operator intent the seat amends; read by all), `persona/` (the judgment seat — how it reasons + its trail), `operation/` (the work the agent operates on/produces), `system/` (orchestration runtime accumulation). Write-permission is a per-caller prefix policy — `_is_path_locked(caller_class, path)`, the agent OS's `access(2)` (Derived Principle 16). This is the topological completion of single-writer: single-writer says *one authoritative writer per path*; this sub-clause says *the directory the path lives in determines the writer-class permission*. The two divergent lock functions (the seat's flat-list + MCP prefix) collapse into one prefix table; `context/_shared/`'s mixing of `/etc`-class + `~/.config`-class + `~/Documents`-class is dissolved into the correct roots. Full derivation, the per-caller permission matrix, and the root file inventory: Derived Principle 25 + [ADR-320](../adr/ADR-320-constitution-region-topological-cut.md) + [ADR-366](../adr/ADR-366-autonomy-mode-as-execution-breadth.md). (The path examples in the single-writer sub-clause above predate ADR-320's re-rooting and read in the legacy `context/_shared/` + `review/` layout; they are swept to the five-root paths in the ADR-320 doc cascade.)

**Amendment — permission is defaulted-by-meaning, owned-by-grant; the namespace carries the *default*, never the *sole* authority (the re-founding, 2026-06-29, REV-2).** The original sub-clause (*"the directory the path lives in determines the writer-class permission"*) is the **single-principal** form: when one principal (the operator + their two embodiments) writes a workspace, *"who writes `persona/`"* has exactly one answer and the prefix is sufficient. The **multi-principal commons** (ADR-373) breaks that sufficiency — many principals co-write one meaning-folder, so per-principal authority *within* a folder cannot be expressed by the prefix alone. The corrected rule, derived from first principles and adversarially verified (the triple-check, REVISE-FIRST verdict):

- **For the work-commons** (operator-meaning folders — the bulk of substrate): permission is a **per-file grant**, **defaulted at creation** by the meaning-folder the file is born in, and **overridden** per-file/per-principal. The gate reads the **file's own grant** for edit/delete — not the path prefix. The directory becomes a **birth-time default-stamp**, not a runtime-permission-source. DP25's "permission is topological" dissolves *here*.
- **The minimal path-anchored residue stays topological** — two regions the keystone's own preserved mechanisms force to keep a path-anchor: **(1) the kernel-read GRANT + per-act floor + `system/`** — because the kernel *locates its own breadth/budget/floor by fixed path* (`load_autonomy` → `governance/_autonomy.yaml`; the wake envelope reads named paths per ADR-281), and because the floor must **deny creation into an empty locked region** (a not-yet-existing file carries no metadata to read — only the path can protect an empty `governance/` path); and **(2) the principal-homes** (`persona/`, `agents/{slug}/`) — fixed identity homes write-protected by owner-metadata, the `/home/alice` model. **DP25 dissolves for the commons; it survives, *minimized*, for the grant + floor + `system/` + the principal-homes.**

**The correct entailment** (sharpened against the triple-check's Attack B): ADR-373 entails permission **cannot live *solely* in the namespace** (the per-principal grant must be overridable per file) — it does **NOT** entail "permission is *never* in the namespace." Directory-as-*default* is fully compatible with the commons; ADR-373 D3 itself keeps `CALLER_WRITE_POLICY` as the per-class default grant with per-principal grants narrowing within — that is the witness. The pre-2026-06-29 absolutist reading (*"permission is metadata, never namespace"*) was falsified at the create-boundary and the kernel's fixed-path grant read, and is corrected to **defaulted-by-meaning, owned-by-grant.** Full derivation: Derived Principle 25 (amended) + Derived Principle 33 + [the re-founding keystone](../analysis/the-re-founding-meaning-folders-and-permission-as-metadata-2026-06-29.md) + the triple-check findings (analysis note, since removed).

### Reality enters only as attributed observation (ADR-335, 2026-06-11)

The seventh sub-clause says *how write-permission is derived*. This eighth sub-clause says **how the world enters**: external reality enters the substrate only as an **observation** — distilled, source-referenced, attested, dated — never raw-mirrored (the ADR-153 line, made axiomatic). **Watches are declared, never crawled**: the operation authors which slice of infinite reality it perceives (the declaration is Layer-1 judgment — a portfolio of attention, `substrate_abi.watches`), and a Trigger reads it on cadence (Axiom 4) — the cadence dial spans once-to-forever, so a one-shot harvest and a standing watch are one observation contract distinguished only by Trigger shape. **Transports are peripherals**: a driver class the kernel knows by contract, never by device; judgment is substrate-aware and transport-blind — attestation (`platform | operator | agent`, the Axiom 8 enum reused verbatim) is the only property that crosses the boundary upward, and it crosses as a property of the observation, never as device-awareness. **Attention is calibrated**: the loop (flow 4, Derived Principle 26) judges which watches earn their keep the same way it judges acts — the trader's `by_signal` expectancy attribution is the existing proof. This sub-clause is the perception-side completion of the third sub-clause (substrate-canonical world): ADR-264 supplies the *mechanism* that mediates external state into substrate; this clause fixes the *form* that mediation takes. See [ADR-335](../adr/ADR-335-perception-field.md).

### The raw observation is retained; understanding is a separate derived act (ADR-376, 2026-06-26)

The eighth sub-clause says *how the world enters* (only as an attributed observation). This ninth sub-clause says **how that observation is retained, and how understanding is built from it**: a contribution to the substrate is **kept raw and never rewritten**, and what the workspace *makes* of it is a **separate, attributed, derived act that cites the raw**. The raw observation is the **source of record** (immutable once written, attributed to the contributing principal); the derived substrate is the **workspace's understanding** (authored by the seat or a deriver, carrying a structured `derived_from` back-reference to the raw it was built from). The two are distinct objects, never the same file rewritten in place. This is the **retention/separation completion of the eighth sub-clause's form-contract**: the eighth fixes that reality enters *as* an observation; this fixes that the observation *persists* distinct from the understanding derived from it — the one git property the authored-substrate clause did not yet carry (a commit never silently overwrites what it records). It generalizes ADR-330's outcome-attestation discipline (raw event-rows folded into a regenerated summary) from outcomes to **all** context-in, and it is what makes the cross-principal `trace` chain (raw contributor → derived reconciliation) *structurally* legible rather than approximately so. The invariant is **retain + attribute + cite**, transport- and format-agnostic; the *mechanism* (a file in a raw lane vs. an attested event-row) is per-transport, so structured intake (outcomes) keeps its event-row raw form and unstructured contribution (MCP, uploads, web, A2A) lands in a raw lane (`inbound/` for machine/external contributions, sibling to the human `uploads/` root — both outside the topology cut, both reasoned-against-never-rewritten). Perception's retention is bounded to the observations a derived act *cites* (the evidence behind understanding), not a crawl archive. Full derivation: Derived Principle 32 + [ADR-376](../adr/ADR-376-ledger-intake-raw-observation-vs-derived-substrate.md) + [the-ledger-intake-axiom analysis](../analysis/the-ledger-intake-axiom-raw-observation-vs-derived-substrate-2026-06-26.md).

**Amendment — raw-vs-derived is a property of *revisions*, not a *namespace* (the re-founding, 2026-06-29).** The **invariant is unchanged** — `retain + attribute + cite` holds exactly. What changes is the **mechanism** for unstructured contribution: the `inbound/` raw *lane* (a separate namespace, sibling to `uploads/`) folds into the **one meaning-file's revision chain** as **observation-kind vs derivation-kind revisions**. A raw contribution becomes an `observation`-kind revision on the file its subject lives in; the understanding an agent derives becomes a `derivation`-kind revision on the same file, carrying `derived_from` as a reference to the observation revision-id it was built from (not a frontmatter line in a separate-lane file). `trace` walks the kind-marked chain; the raw is retained (the revision is immutable, ADR-209), attributed (`authored_by` on the revision), and cited (the derivation's `derived_from`). **This couples to the sixth sub-clause** (above): folding raw *into* the meaning-file's chain ends the per-`{transport}/{principal}` single-writer isolation the raw lane gave it, and *manufactures* the same-path multi-principal write — so this fold and the single-writer relaxation are **one move**, and the structured-attested raw form (Axiom 8 outcome event-rows) is unaffected (it was never an `inbound/` file). The "outside the topology cut" framing in the clause above is superseded by the seventh sub-clause's amendment (the cut is minimized to the grant + principal-homes; the commons carries provenance as revision-kind, not as a lane). See [the re-founding keystone](../analysis/the-re-founding-meaning-folders-and-permission-as-metadata-2026-06-29.md) Test 3 + the triple-check findings (analysis note, since removed) §8.

## Axiom 2: Identity — Agents and Machinery

**Every act has an identity. Every file has an author. Identity is orthogonal to mechanism.**

YARNNN separates **agents** — the colleagues a member works with — from **machinery** — kernel code that executes unconditionally under a `system:` attribution. Only agents and the humans they work for are Identity-bearing in the axiomatic sense. Machinery has no standing identity; it is stateless infrastructure per Axiom 1. See [LAYER-MAPPING.md](LAYER-MAPPING.md) for the taxonomy and [GLOSSARY.md](GLOSSARY.md) for vocabulary.

> **Recut (2026-09-12, v10.0).** This axiom's seat-era body — the Freddie/Reviewer member table, "the seat's distinctness is in Purpose + Trigger," the operator's two embodiments, the ADR-284 standing-intent home and the development-axes table — described machinery ADR-632 deleted and an agent model ADR-596 replaced. It is archived verbatim at [previous_versions/FOUNDATIONS-v9.20-2026-09-12.md](previous_versions/FOUNDATIONS-v9.20-2026-09-12.md) §Axiom 2. The text below states the live form.

### An agent is identity ⊕ character ⊕ engine, and nothing else (ADR-596 D1)

An **agent** is a named colleague — an identity (who), a character (how it works: posture, register, craft), and an engine (which model runs behind the name). That is the whole thing. **Authority, reach, clock, purpose and judgment are never properties of an agent**: they live on grants (who may act where — `principal_grants`, ADR-373/405), on declarations (what standing work is owed — ADR-603), and on gates (chokepoint code that fails closed — ADR-307/643). Nothing an agent's own files say can widen what it may do (ADR-460 D3.a: no authority-shaped field on any agent, ever).

Three things are not agents, and the distinction must not blur:

- **Machinery** — kernel code executing unconditionally, attributed `system:*`. It has no home, no grants, no character of its own; it is trusted because it is reviewed *as code*. It may wear an agent's costume for display (a standing declaration's run resolving the app's resident) while attributing `system:standing`.
- **The human root of the grant chain.** Every grant chains to a workspace owner, and owners are persons — not because the OS cares about species (it does not: ADR-405, no rule keys on human-vs-AI), but because liability terminates outside the OS.
- **Gates** — chokepoint code, fail closed. Policy may be declared in substrate; enforcement is never substrate.

### One register; the app carries the capability (ADR-600/601)

There is one register of agents (`AGENTS` in `api/services/agents_registry.py`). Capability lives at the **app** — the surface an agent works in — so many agents can share one app and one agent can serve several (Editor → slides · text; Designer → images). An agent is met, not audited: no surface presents work, output, cost or history *attributed to an agent* (ADR-640); the ledger attributes every revision to the acting **member** via the agent, and the agent's craft and tending are the only derived views it has.

### The member is the principal; the lane is their embodiment

A **lane** is a member's conversation with one agent under the member's own grant (ADR-411/558). It is not a principal: the member is the principal, the lane is how they act through an agent. Lanes are isolated conversations; **the workspace is the shared memory** — agents collaborate through the filesystem with attribution, never through each other's transcripts. Standing work (ADR-603/639) is the unattended form: a member's declaration, executed by the app's resident, attributed `system:standing`, contract-checked and receipted.

### Identity manifests through filesystem (ADR-624)

Per Axiom 1, identity is carried by substrate, not held in code:

- **An agent's home** — `agents/{slug}/` holds exactly two things: `memory/` (what the agent knows — freely writable by it, ordinary substrate) and the two locked grant sidecars (`_autonomy.yaml`, `_budget.yaml`). It is a principal home, not a semantic root; nothing there confers purpose, clock or judgment.
- **A member's identity** — the account and its grants; a member has no file the kernel reads for authority.
- **Kernel-mirrored identity facts** — `system/agents/{slug}/` carries what the kernel ships for an agent (its face, its character); a member's own `agents/{slug}/face.png` wins (ADR-641 am.2).

A file without a declared author identity is an Axiom 2 violation. An agent acting without a resolvable identity is a bug. Machinery does not author files in its own name beyond `system:{actor}`; a write done in a lane carries the member's attribution via the agent.

### Agents develop through what they know, not through what they are

An agent's tenure accumulates in its `memory/` (ADR-624) and in the workspace's own record; its identity, character and engine do not drift with use. Capabilities are the app's and are fixed at registration; nothing is earned through seniority. What compounds is the substrate — the commons every agent reads — and the member's calibration of how each agent's output should read.

## Axiom 3: Purpose — Intent Lives in Substrate

**Every mechanic has a Why. The Why lives in a file.**

Purpose is what intent drives the work. It is declared in substrate files:

- **Workspace purpose** — `/workspace/context/_shared/MANDATE.md`, `/workspace/context/_shared/IDENTITY.md`, `/workspace/context/_shared/BRAND.md`, `/workspace/context/_shared/CONVENTIONS.md`, `/workspace/context/_shared/AUTONOMY.md` (post-ADR-206/217 relocation). What the operator is building, how they think, what they care about, the structural rules all agents honor, and how much judgment authority the AI carries on their behalf.
- **Operation purpose** — `/workspace/context/{domain}/_operator_profile.md` + `/workspace/context/{domain}/_risk.md`. Declared rules, signals, limits — the *edge hypothesis* the operator is running. Post-ADR-206 these files are the Intent artifacts that drive the loop.
- **Task purpose** — `/tasks/{slug}/TASK.md` (objective) + `/tasks/{slug}/DELIVERABLE.md` (output specification). Why this task exists, what it produces.
- **Agent purpose** — not on the agent (ADR-596 D1). What an agent may do is its grant (`agents/{slug}/_autonomy.yaml` + `_budget.yaml`, locked — ADR-624); what it is for in a given piece of work is the member's ask in the lane or a standing declaration's `CONTRACT.md` (ADR-603). A grant can narrow the workspace's ceiling, never widen it.
- **Agent purpose** — `/agents/{slug}/AGENT.md`. What domain the agent owns, how it approaches its domain.
- **Domain purpose** — `/workspace/context/{domain}/_domain.md`. What this domain tracks, what entities belong in it.

### Purpose can also be carried by Identity's known context

Not every Purpose needs to be substrate-declared. When an Identity takes a well-defined action (operator uploading a PDF to Context, user clicking Approve on a ProposalCard), Purpose is inferrable from the Identity's role and the interaction shape. The model allows Purpose to be carried by Identity when not substrate-declared — Substrate is preferred for persistent purposes, Identity is sufficient for per-action purposes.

### Rule: a mechanic without Purpose is dead code

Every shipped mechanic must be answerable to the Why question. If a mechanic fires but no substrate or identity declares *why*, it is either dead code or a drift (a mechanic that once had purpose and lost it). Axiom 3 is the conscience that prevents accumulation of purposeless mechanics.

### Corollary: the operator-facing three-layer view (ADR-206)

Purpose, from the operator's perspective, is triangulated across three orthogonal layers. The layers are orthogonal to Axiom 2's four-layer cognition model (which describes *who acts*); these three describe *what the operator interacts with*.

| Layer | What it is | Where it's authored / surfaced |
|-------|-----------|--------------------------------|
| **Intent** | Declared rules, risk limits, principles, success criteria. The operator's edge hypothesis. | Authored at `/workspace/context/_shared/*` + domain `_operator_profile.md` + `_risk.md` + `/workspace/review/principles.md`. Rendered on `/context`. |
| **Deliverables** | Externalized outputs of the operation. Proposals awaiting approval, briefs, weekly reviews, `_money_truth.md` snapshots. | Surfaced on `/work` list-mode (primary) and `/review`. |
| **Operation** | Execution substrate: tasks, agents, reconcilers, scheduler. | Drill-down on `/work` detail mode and `/team` — second-class to the operator. |

The loop the operator runs: **Intent → Operation → Deliverables → Intent (refined).** Reports and briefs are side-effects of the loop running, not the point of the loop. Axiom 3 Purpose is first-class in the Intent layer; Axiom 2 Identity fills the Operation layer; Axiom 6 Channel renders the Deliverables layer.

Axiom 3's "Purpose can also be carried by Identity" rule maps directly here: substrate-declared Purpose lives in Intent; interaction-inferred Purpose (operator clicks Approve on a proposal) lives in the Deliverables layer's action affordance.

## Axiom 4: Trigger — Every Invocation Has a When

**Every invocation has a When. Nothing runs on its own initiative: a turn is either a member's act or a member's standing declaration coming due.**

> **Recut (2026-09-12, v10.0).** The seat-era body of this axiom — five wake sources, the evaluation funnel, the wake queue and drainer, cron-tick recurrence dispatch, `_recurrences.yaml` + `_hooks.yaml`, the Schedule/ManageHook primitives — was deleted by ADR-632 and ADR-603 D5. It is archived verbatim at [previous_versions/FOUNDATIONS-v9.20-2026-09-12.md](previous_versions/FOUNDATIONS-v9.20-2026-09-12.md) §Axiom 4; ADR-626's amendment records why nothing wakes on its own any more (spend without a witness, a clock on an agent, no contract).

### Two trigger shapes, and only two

| Shape | The When | Who is the trigger | Execution path |
|---|---|---|---|
| **Attended** | A member sends a message in a lane. | The member. | `run_lane_turn` — the agent's tool-use loop under the member's grant (ADR-411/558). |
| **Unattended** | A standing declaration's schedule comes due. | The member who declared it, one declaration earlier. | The kernel's one drain loop (`api/services/scheduling.py`, ADR-639) → `run_bounded_derive_turn`: toolless, contract-checked, bounded by the pool (ADR-618), receipted. |

Both shapes are the member's. There is no third: no source that proposes its own wake, no funnel that decides whether judgment is warranted, no agent that fires because something changed. A change in the world reaches the substrate through intake (Axiom 1's third clause) and is *read* on the next turn; it does not *cause* one.

### Standing work is a declaration, not a clock on an agent (ADR-603/639)

A **standing declaration** lives beside the file it keeps: `{folder}/_standing.yaml` (the schedule, the sources, the app) + `CONTRACT.md` (what "true" means for the kept file). A member declares it from inside any lane (the `declaring-standing-work` skill) and the kernel drains it; the run rewrites the kept file or records an honest no-op, and every run is a receipt on the timeline. The app derives from the kept file's type; an agent is never the subject of a declaration. Capture (ADR-582/591) is the intake twin — a connection's observations landing on schedule — and rides the same loop; a third unattended kind is an adapter on that loop, never a second scheduler.

### Corollary: the member's ask is the default trigger; a schedule is a declaration

A request to "do this" is an attended turn. If the same work should recur, the member declares it standing — with a contract, so "did it work?" is answerable. Recurrence without a contract is what ADR-603 D5 retired: a clock that shared nothing with the work it fired.

### Time is an envelope concern, not a substrate concern

An agent perceives *now* on each turn — the frame carries the time in the workspace's home timezone — not by reading workspace state. This mirrors Claude Code's runtime model: time is contextual input on each invocation, not persisted memory between invocations.

### Mid-turn continuation is not a trigger

Inside a turn, every tool call returns and the agent reads the result. That is the shape of a tool-use loop, not a separate trigger; a turn starts once and ends once.

## Axiom 5: Mechanism — Spectrum from Code to Judgment

**Every act has a How. How varies continuously from deterministic code to LLM judgment.**

Mechanism is the means by which work happens. One dimension with a spectrum:

| Position on spectrum | Character | Examples |
|---|---|---|
| **Fully deterministic** | Pure Python, zero LLM. Output is a function of input. | Daily-update empty-state template, `_money_truth.md` frontmatter folding, workspace cleanup, section-kind renderers, risk-gate rule checks, PostgREST queries, the standing-work drain and capture lanes (ADR-639/582), the compose engine (ADR-417), the access decider (ADR-643) |
| **Mixed** | LLM with tight structural contract. Output shape is declared; content is judged. | Inference (IDENTITY.md, BRAND.md, context domains), specialist sub-LLM-calls (researcher, analyst, writer, etc. — `headless` runtime characteristic with focused prompts per ADR-261 D7) |
| **Fully judgment** | LLM orchestrating with broad latitude. Output is the model's call. | A lane turn (`run_lane_turn`) — the agent's tool-use loop under the member's grant: reading, judging, writing, deciding when the turn is done. |

The three points on the spectrum map cleanly to **roles in the unified execution model** (per ADRs 257 / 260 / 261):

- **An attended lane turn** sits at fully-judgment: the agent's real-time tool-use loop under the member's grant (Axiom 2).
- **Specialists** sit at mixed. Focused-prompt sub-LLM-calls invoked through `headless` runtime mode. Researcher / analyst / writer / tracker / designer / reporting per ADR-176. They run with their own contexts — same shape as Claude Code sub-agents.
- **Machinery** sits at fully-deterministic: the scheduler's drain loop, capture, compose, the gates. No LLM judgment in the execution path. A **bounded derive turn** — a standing declaration's run (ADR-603/618) — sits between: judgment inside a contract, toolless, checked and receipted.

What was previously framed as ADR-141's "three execution layers" (Mechanical / Generation / Orchestration) is reshaped under ADR-261: the legacy headless task pipeline is dissolved; an agent does its production work inline in its own turn, not through a separate execution path. The spectrum stands; the mapping is now lane turn / bounded derive turn / machinery (ADR-632).

### Primitives are the vocabulary of Mechanism

LLM reasoning in YARNNN speaks through primitives — typed verbs with substrate and permission scope (see [primitives-matrix.md](primitives-matrix.md)). Primitive design is the engineering of Mechanism's vocabulary:

- **Adding a primitive** = extending Mechanism's vocabulary. Requires ADR + rename protocol sweep (CLAUDE.md rule 7b).
- **Scoping a primitive by mode** (chat / headless / MCP) = restricting which Identity can use which vocabulary word.
- **Prompting strategy** = configuring which vocabulary words the LLM reaches for, in which situations. Prompt profiles (ADR-186) are the configuration surface.

**Tool use and prompting are not separate concerns.** They are the two halves of Mechanism's judgment spectrum — prompts shape the reasoning, primitives are the output grammar. Designing one without the other is a dimensional conflation.

### The loosening rule (Spectrum B from YARNNN-DESIGN-PRINCIPLES)

Mechanism loosens over time. Today's codebase is procedural-heavy (pre-gather → single generation → compose → deliver). The direction of travel is toward more judgment at the Mechanism layer, but this loosening is gated by grants, the witness gate (ADR-307/405) and contracts (ADR-618) — authority held off the agent is what makes runtime autonomy safe.

Substrate rules tighten over time (Axiom 1). Mechanism rules loosen. These are the two spectrums YARNNN-DESIGN-PRINCIPLES names.

## Axiom 6: Channel — Output Is Addressed

**Every act has a Where. Where is either Substrate itself or an addressed destination.**

Channel is where output goes. Two sub-shapes:

1. **Substrate-return** — output is written to the filesystem and becomes part of accumulation. Examples: a lane writes an artifact into a meaning folder; a standing declaration rewrites its kept file; capture lands an observation in `inbound/`; an agent appends to its `memory/`. No external addressing.
2. **Addressed** — output is delivered to a cognitive consumer outside the substrate. Examples: email to operator; Slack/Notion/GitHub write-back to platform; ProposalCard rendered in chat; surface view in `/work` or `/agents` or `/context`; platform write-back via `submit_order`, `create_discount_code`, `send_email`.

### Addressed channels have subcategories by cognitive consumer

Axiom 2 says every Identity has a distinct scope. Addressed channels inherit this — the cognitive consumer determines the channel's affordance:

| Consumer | Channel shape | Examples |
|---|---|---|
| Operator (human user) | Surfaces + email | Chat surface, Work surface, Agents surface, Context surface, daily-update email, ProposalCard |
| External platform | Platform API writes | Slack post, Notion block write, Alpaca order submit, Lemon Squeezy discount creation |
| Another Identity within YARNNN | Substrate (see sub-shape 1) | an agent writes a file that another agent's turn later reads; a standing declaration keeps a file a lane cites |
| Foreign LLM (via MCP) | MCP response to `pull_context` / `work_on_this` / `remember_this` | QueryKnowledge results, composed subject bundles |

### Channel ≠ Mechanism

Compose substrate (ADR-170 / ADR-177) sits at the joint between Mechanism and Channel:
- **Rendering HTML to a file** = Mechanism (substrate-return Channel)
- **Addressing that HTML to a surface or email** = Channel (different consumer, same file)

The file is the durable artifact (Substrate). The rendering is how it was produced (Mechanism). The delivery routing is where it goes (Channel). Three dimensions, one artifact. Compose substrate is the legitimate cross-cut that deliberately couples Mechanism + Channel — and its legitimacy is justified by the singular output-substrate argument in ADR-148 + ADR-170.

Cross-cuts are not always errors. They are errors when unjustified.

### The Home is a composition over present constituents (ADR-312)

The operator-facing surface is not a fixed program dashboard; it is a **composition over the workspace's present constituents** ([ADR-312](../adr/ADR-312-home-as-composition.md)). Every workspace — trader, author, partnership manager, A&R, SCM, engineer — has the same six constituents at different weights; the weight-shift is exactly what a *program* declares. The kernel owns a fixed set of six Home slots (constitution band · ground-truth hero · decision queue · live entities · recent artifacts · judgment trail) and their order; the program weights, labels, and shapes each slot via the compositor (ADR-225). It does not invent slots. Absent constituents do not render — the Home is honest about what exists, so a bare kernel renders substrate-forward (the constitution-band CTA), not as a de-activated program dashboard. **The kernel never hardcodes a program noun in a slot** (no "Positions," no "money-truth" as kernel default); slot #2's ground-truth hero and slot #4's live entities are generic contracts the program binds. This is the Channel-dimension expression of Axiom 1's substrate-by-role taxonomy (ADR-281): the Home composes constitution / context / artifacts / trail by substrate role. The two windowed registers (ADR-309) refine to three (ADR-312 D5): `intent` (the constitution), `os-config` (the OS configuring itself), `application` (open files + live state).

## Axiom 7: Recursion — The Six Dimensions Compose Over Time

**When the six compose, accumulation happens. Accumulation is the compounding mechanism.**

Recursion is not a seventh dimension. It is what the first six *do* over time. One cycle of the architecture:

```
Trigger (when)
  → Identity + Purpose decide what matters (who + why)
    → Mechanism reads Substrate, reasons, produces output (how, reading what)
      → Channel addresses output to destination (where)
        → Substrate accumulates (what, extended)
          → next Trigger reads richer Substrate ...
```

The cycle is the architecture. Every mechanic participates; some mechanics visit all six cells in one firing (task pipeline), some visit a subset (cleanup cron: Trigger + Substrate + Mechanism).

### Four layers of recursive perception

Perception is Substrate-read (Axiom 1) with zero Mechanism. Four layers of perception feed each Mechanism cycle:

1. **External perception** — Agents call platform APIs (Slack, Notion, GitHub, Alpaca, LS) live during task execution. Raw platform signals processed by agents and written as structured context to `/workspace/context/` domains. Per Axiom 1, no intermediate staging table (ADR-153: `platform_content` sunset).

2. **User-contributed perception** — uploaded documents in `/workspace/uploads/`. Permanent reference material the user explicitly shares. Triggers inference to update workspace context (IDENTITY.md, BRAND.md).

3. **Internal perception** — accumulated workspace context at `/workspace/context/` + task outputs in `/tasks/{slug}/outputs/`. Each run's output feeds the next run's context. Context domains accumulate cross-task intelligence that any Identity can draw from.

4. **Reflexive perception** — user feedback (edits, approvals, dismissals, conversational corrections), YARNNN's observations (`/workspace/notes.md`, `/workspace/style.md`), witness verdicts (`action_proposals`, ADR-307), money-truth reconciliation (`_money_truth.md`). As time progresses, this accumulated judgment becomes the most valuable signal — more valuable than raw platform data.

### Three substrates for coherence

Perception flows through three distinct **views onto the same filesystem substrate** (Axiom 1) that must stay coherent:

1. **Conversation** — sessions, chat messages, compaction (`/workspace/awareness.md` + session records). What was said.
2. **Filesystem** — workspace files (`AGENT.md`, `memory/`, `TASK.md`, cognitive files, context domains). What the system knows.
3. **Agent cognition** — role prompts, task process declarations, execution strategies. How agents think (this is Mechanism reading Substrate).

Three views are not hierarchical. Intelligence degrades when they fall out of sync: a user directive in conversation that doesn't reach the filesystem evaporates on session rotation; an assessment in the filesystem that agents can't read produces blind spots.

### The recursive property

```
External platforms → live API calls → agent execution → task output →
  /tasks/{slug}/outputs/ + /workspace/context/ → next agent execution → ...
       ↑                                          |
       └── user uploads (/workspace/uploads/) ────┘
       └── user feedback (/workspace/style.md) ──┘
       └── witness verdicts (action_proposals) ─────────┘
       └── money-truth (_money_truth.md) ────────┘
       └── YARNNN observations (/workspace/notes.md) ─┘
```

The workspace filesystem acts as an **operating system for agent and human work** — a shared substrate where both contribute and both consume. The filesystem IS the information architecture.

### Implication: Optimize for accumulation, not extraction

External platform integrations are the onramp. The enduring value is in the recursive accumulation: agent memory, learned preferences, domain theses, cross-agent insights. As LLM capabilities improve, the quality of each recursive cycle improves — the system's reasoning gets better at the same substrate. This compounds. Architecture decisions should prioritize the health of this recursive loop over the breadth of external integrations.

## Axiom 8: Ground-Truth Substrate — Substrate Must Carry Reconciled Consequence-Bearing Reality

**Reconciled outcomes the operator personally bears the consequences of belong in the filesystem, per domain, per operator, per cycle.**

> **Relocation note (2026-07-07, v9.16 — ADR-414 D6, per ADR-382 §3):** the axiom is kernel-invariant and unchanged; *where its loop attaches* moves. The ground-truth loop (outcomes-in, calibration, the consequence pipe) is a property of a **hired Altitude-3 persona agent's operation**, homed with that agent (`agents/{slug}/`), never of the workspace as such and never of the system agent — a bare workspace has no ground-truth substrate because it bears no operation's consequences, and that is coherent, not incomplete. **Parked, not deleted**: the machinery (reconciler, attestation, `_money_truth.md` instance) continues on the live dogfood operation, re-homed with the first hired agent (ADR-414 D5); the axiom governs every future hire from its first act.

YARNNN is not just a knowledge-work platform — it is an **action platform**. Per ADR-192 + ADR-193, agents can write to external platforms (trading orders, commerce product updates, campaign emails) and operators author artifacts that compound (corpus, drafts, decisions). Those writes have *consequences the operator bears*. The system must close the loop: every action must be reconciled against ground-truth reality and the reconciled outcome must live in Substrate where agents and the operator can read it.

### Three structural properties of ground-truth substrate

1. **Consequence-bearing.** The signal is not neutral data. The operator winces when it moves the wrong way. This is what makes it *truth*, not just observation.
2. **Substrate-grounded.** It flows back into the workspace filesystem as readable substrate, not living only in the operator's head or in an external dashboard. Per Axiom 1. No sibling SQL ledger.
3. **Calibratable.** An agent can read it and adjust judgment over time. Calibration is the mechanism by which judgment improves against accumulated outcomes.

A fourth property follows for instances reconciled from external systems: **idempotent under replay**. The reconciler can run any number of times; output is deterministic modulo external history. Idempotency keys live in file frontmatter (per ADR-195 v2 for alpha-trader's instance).

### Three asymmetric bets ground-truth substrate enables

1. **An agent can reason against reconciled reality, not just rules.** Without ground-truth substrate, decisions collapse to rule-checking. With it, an agent can reason "you're already 40% tech-concentrated, this trade is outside your edge" (alpha-trader instance) or "this draft contradicts your stance in last month's piece" (alpha-author instance) — judgment grounded in accumulated outcome, not just declared principle.
2. **Operator-borne consequence becomes perception, not infrastructure.** Whether revenue (ADR-184 product health), corpus coherence (alpha-author), or capital P&L (alpha-trader), the signal flows into the workspace as context the same cognitive layers read for every other perception.
3. **Accumulation compounds across action.** A tenured workspace + accumulated ground-truth substrate is a different product than a tenured workspace without. The reconciled substrate is what makes "the operation gets better at its job, measured by the outcome the operator bears" a structurally grounded claim rather than a marketing line.

### Per-instance illustration

Axiom 8 holds across domains; the *signal shape* varies. Three current instances:

| Instance | Signal | Substrate home | Latency | Attribution | Calibration shape |
|---|---|---|---|---|---|
| **alpha-trader** (money-truth) | Reconciled order fills + position state from Alpaca | `/workspace/context/{domain}/_money_truth.md` (ADR-195 v2) | Minutes to hours | Per-trade clean | Capital-EV reasoning per proposal |
| **alpha-commerce** (revenue-truth) | Subscription events, refunds, payment confirmations | `/workspace/context/revenue/_money_truth.md` (ADR-183 + ADR-184) | Minutes (event) to weeks (cohort) | Per-product, weaker per-action | Product-decision EV |
| **alpha-author** (corpus-coherence + multi-signal, per ADR-283) | Composite: internal corpus coherence + audience signal when present + revenue when present | `/workspace/operation/authored/_signal.md` (declared `substrate_abi.ground_truth` per ADR-330 D4) | Continuous (coherence) to months (revenue) | Cohort/pattern-level, **multi-attestation** (platform/operator/agent per row, ADR-330) | Editorial discipline across corpus |

The illustration shows: **the axiom holds. The signal shape varies by domain. The architectural property is invariant.**

### Revenue as one instantiation, not the universal

Accumulated attention (Axiom 7) is invisible without external validation. For content product businesses, **revenue is one valid ground-truth signal** — if quality genuinely improves over time, subscribers notice, retention rises, revenue grows. Switching to any other tool means starting from zero context. The same compounding-validation property holds in non-monetary instances: for an alpha-author screenplay workspace, *internal substrate coherence* (agent-detected continuity across the corpus) plays the validation role until external signal arrives.

Three-tier metrics hierarchy (ADR-184) — product health upstream, driven by task quality, driven by agent health — generalizes to: **ground-truth signal upstream, driven by output quality, driven by agent health.** Revenue is the cleanest available signal in monetary-domain instances. The kernel axiom does not require monetary signal; it requires *consequence-bearing reconciliation*.

### Ground-truth intake — the consequence pipe (ADR-330)

Axiom 8 names the *substrate* (ground-truth must live in the filesystem). ADR-330 names the *flow that fills it* and the *mechanism that carries it* — flow 3 of the four-flow operation loop (Axiom 9 + ADR-332):

- **Ground-truth intake** — flow 3, *outcomes in*: reality's verdict on the operation's own acts flowing back into substrate. This is the moat: *judgment calibrated against ground truth the agent cannot author.* It generalizes beyond platform APIs — an operator whose ground truth isn't an Alpaca or Lemon Squeezy API hands the system their own records (CSV import, retrospective backfill). The universal fallback exists so cold-start calibration works for every operator, not just two verticals.
- **Consequence pipe** — the mechanism: the reconciler + its providers turn reality's verdict into substrate. One pipe, many producers (a platform API, the operator's own import, a future agent harvest), folding idempotently into the per-domain ground-truth file. The code-level names (`OutcomeProvider`, `OutcomeCandidate`, `reconcile_user`) are preserved per ADR-282 + ADR-330 D5 — the concept misled, not the symbol.

**Attestation — who vouched (ADR-330 D2).** Generalizing flow 3 beyond independent platform APIs would silently dilute the moat unless every row records *who attested it*. Three levels, each preserving or qualifying the moat honestly:

- `platform` — external API independent of operator **and** agent. **Gold.** The moat claim is unqualified.
- `operator` — the operator's own import (CSV, manual, operator-proxy). **Strong.** The agent still can't fake it (the calibrated thing isn't vouching); the operator can bias it. The claim narrows from "judged against reality" to "judged against **your own records**" — an acceptable qualification (an operator who lies to their own loop only fools themselves).
- `agent` — an agent read/asserted the number. **Weak, conditional.** The calibrated thing participates in producing its own evidence. Admissible only as labeled, corroboration-seeking evidence; calibration must never let an agent-attested row silently raise confidence the way a platform row does.

**Label-first, not weight-first.** Calibration records + surfaces the attestation level on every row; weighting by attestation is a deferred follow-on (added when evidence shows label-only insufficient). This keeps the loop honest now (strength never hidden) without prematurely encoding a weighting curve. **Retrospective backfill** (operator import of pre-YARNNN history) is segmented, not blended — kept out of the live rolling windows so a historical dump never reads as recent performance. Attestation says *who vouched*; retrospective says *is this backfill* — orthogonal.

### Vocabulary discipline

`money-truth` is alpha-trader's instance-level term for this axiom. Per ADR-282:

- When a canonical doc means *the axiomatic property*, say **ground-truth substrate** and cite Axiom 8.
- When a doc means *alpha-trader's reconciled-P&L substrate at `_money_truth.md`*, say **money-truth** and cite the alpha-trader bundle.
- Sentences that legitimately use both in instance-of relationship (e.g., *"alpha-trader's money-truth is the cleanest instance of ground-truth substrate"*) are correct.

`_money_truth.md` filename, `services/outcomes/*.py` module, `OutcomeProvider` ABC, `TraderMoneyTruth` component, `cockpit.money_truth` binding key, and `/api/cockpit/money-truth` route are all **alpha-trader instance-level identifiers** and are preserved unchanged.

## Axiom 9: Invocation and Narrative — The Atom and Its Log

**One cycle of the six dimensions is an invocation. Every invocation surfaces in one narrative.**

Axiom 0 names the six dimensions the system must separately decide. Axiom 7 names what happens when they compose over time (Recursion). Axiom 9 names what happens when they compose **once** (Invocation) and where each composition becomes legible to the operator (Narrative).

### Clause A — Invocation is the atom of action

An **invocation** is one cycle through the six dimensions: one actor (Identity) is fired by one trigger (Trigger) for a declared purpose (Purpose), applies some mechanism (Mechanism), reads and writes substrate (Substrate), and emits output to some channel (Channel). When the cycle terminates, the invocation is complete. Nothing persists in the actor — state lives only in the substrate it wrote (Axiom 1) and in the narrative entry it emitted (Clause B).

The invocation shape is **actor-class-agnostic**. Agents in a lane, standing declarations, machinery (`system:` actors), and external callers (foreign LLMs via MCP, webhook senders) all emit invocations of the same shape. The Identity slot varies; the atom does not. This is what makes MCP a fifth caller of `execute_primitive()` (ADR-164 / ADR-169) without a parallel dispatch machinery — a foreign LLM call *is* an invocation with Identity = `external:<client>`.

**Pulse** is the actor-scoped name for the Trigger sub-shape — Trigger viewed through the Identity lens. An attended lane is member-pulsed (the member's message is the trigger); a standing declaration is schedule-pulsed (its own clock, drained by the kernel). Pulse is not a new dimension.

### Clause B — Narrative is the universal invocation log

Every invocation emits an entry in a **single narrative** — the chat-shaped operator-facing log of everything the system did. Ordered by time. Attributed by Identity (Axiom 2). Filterable by Agent, by task-nameplate, by pulse sub-shape. The operator returning tomorrow sees the narrative and can answer *"what happened while I wasn't watching"* without opening a parallel surface.

The narrative is not "the chat feature." It is the Axiom 6 Channel that closes Derived Principle 12 (Channel legibility gates autonomy): autonomous invocations become legible by surfacing here. The operator's own messages are one thread in the narrative; agent replies, standing-declaration runs, witness verdicts, captures, MCP calls — all are threads in the same narrative.

Not every invocation deserves equal visual weight. The narrative has a **material / routine / housekeeping gradient** — a rendering policy, not a logging policy. Every invocation emits an entry; weight determines whether it surfaces as a prominent card, a collapsed line, or a rolled-up digest ("12 housekeeping invocations, all clean"). See [invocation-and-narrative.md](previous_versions/invocation-and-narrative.md) §3.

The narrative also rolls up daily into `/workspace/memory/recent.md` (ADR-221) — material non-conversation entries grouped by Identity, filesystem-native, read on demand by YARNNN at prompt-time. Counterpart to ADR-209's substrate-authorship one-liner: substrate axis answers "who wrote what file"; narrative axis answers "what invocations happened." Two complementary one-liner pointers in the compact index, full detail in filesystem files.

### Clause C — Tasks are legibility wrappers, not parallel substrates

A **task** is a nameplate + pulse + contract attached to a category of recurring (or goal-bounded, or reactive) invocations. The nameplate is a stable slug + TASK.md. The pulse is the future trigger shape. The contract is DELIVERABLE.md (for `produces_deliverable`) or the context-domain mapping (for `accumulates_context`).

Tasks do not create a parallel log. `/work` is a **filtered view of the narrative** scoped to task-labeled invocations. This reframes ADR-138 ("agents as work units") without changing the implementation: the substrate — `/tasks/{slug}/outputs/`, context writes, `agent_runs` — is unchanged; the mental model sharpens. The atom is the invocation; the task labels a stream of atoms.

**Inline actions are invocations without a nameplate.** "Pull today's revenue" is one invocation, one narrative entry, no task. "Do that every morning" attaches a nameplate + periodic pulse to future invocations; the next firing is structurally identical to the inline one, differing only in that its narrative entry now carries the task slug. The inline-to-task transition is gradient and reversible (nameplate-attach, nameplate-detach) — not a substrate migration.

### Implications

- **`/chat` is the narrative surface**, not a conversation feature. Operators don't travel there; they return there.
- **`/work` is the narrative filtered by task slug**, not a parallel `agent_runs` view. Data shape unchanged; conceptual model collapses.
- **Every autonomous invocation has a legible home** — the narrative entry. Principle 12 becomes structurally enforceable rather than aspirational.
- **Task modes are lifecycle posture, not invocation trigger.** ADR-149's `recurring / goal / reactive` describe YARNNN's management posture across invocations (evaluate, steer, complete); pulse describes how each invocation fires. Orthogonal layers.

Deep dive (archived with the steward, ADR-632): [previous_versions/invocation-and-narrative.md](previous_versions/invocation-and-narrative.md). Implementation phasing: ADR-219 (proposed).

## Derived Principles

These follow from the axioms and are stated explicitly for implementation guidance:

1. **Dimensional purity** — No mechanic should span dimensions without explicit justification. When a design decision conflates dimensions (e.g., ADR-195 v2 Phase 4's proposed briefing-absorbs-performance), the conflation is caught by the dimensional test and redesigned. Cross-cuts are legitimate only when argued for (e.g., compose substrate deliberately couples Mechanism + Channel per ADR-148's singular-rendering-path argument).

2. **Substrate is the shared OS** — All persistent state lives in the filesystem roots: the workspace's meaning folders (`operation/` and the folders members name), `inbound/` (what arrived), `uploads/`, and `agents/{slug}/` (memory + grant sidecars). New capabilities extend paths, not database tables.

3. **Agents are the write path** — All modifications to workspace files flow through Identity-authored primitive calls, not direct user manipulation. The frontend is read-only on workspace (operator feedback is routed through primitive calls). User intent goes through YARNNN → agents. This protects the structural conventions.

4. **Accumulation over extraction** — Prioritize the health of the recursive accumulation loop (Axiom 7) over the breadth of external integrations. Internal and reflexive perception layers are more valuable long-term than the external layer.

5. **Identity develops by its axis; capability is fixed** — An agent develops through its memory (ADR-624); a member's calibration accumulates in the commons. Capabilities are the app's, fixed at registration (ADR-596/600) — not earned through seniority.

6. **Feedback is perception** — User edits, approvals, and dismissals are first-class Reflexive-perception signals, equivalent in architectural importance to platform data. They drive both Agent development (Axiom 2) and YARNNN's compositional judgment (Mechanism spectrum).

7. **Singular implementation** — One way to do things. If YARNNN composes, there is no separate Composer. If tasks subsume scheduling, there is no parallel trigger system. If the kernel has one drain loop, a second unattended kind is an adapter on it, not a twin (ADR-639 D3).

8. **Work is bounded** — Autonomous work (agent runs, assemblies, renders) consumes tokens (ADR-171) and balance (ADR-172). The `balance_usd` gate is the sole budget — no parallel tier limits.

9. **Mechanism is a spectrum, not a split** — ADR-141's three layers (mechanical / generation / orchestration) are three points on Mechanism's determinism-to-judgment spectrum, within one dimension. Primitives + prompts are the two halves of Mechanism's vocabulary — designing one without the other is a dimensional conflation.

10. **Registries are template libraries, not validation gates** — The task type registry, directory registry, and agent templates are curated libraries of domain-specific patterns (ADR-188). YARNNN can draw from them or compose novel definitions. The execution pipeline reads workspace files (TASK.md, AGENT.md, `_domain.md`) at runtime, not the registries.

11. **Substrate tightens; Mechanism loosens** — Over time, Axiom 1's substrate discipline grows stricter (fewer DB tables holding semantic content, cleaner file conventions). Axiom 5's mechanism grows looser (more agent autonomy, less procedural scaffolding). Grants and gates (Axiom 2, ADR-307/643) are the pivot that makes Mechanism loosening safe. See [YARNNN-DESIGN-PRINCIPLES.md](YARNNN-DESIGN-PRINCIPLES.md) "The Two Spectrums."

12. **Channel legibility gates autonomy** — Autonomous writes must have a legible Channel back to the operator (approval UX, daily-update pointers, dedicated surfaces). An action without a visible channel is a trust leak — the operator cannot supervise what they cannot see. This is why surface archetype design (ADR-198) is load-bearing for the autonomous-operator ICP.

13. **Substrate writes are attributed and retained (Authored Substrate)** — Every mutation to `workspace_files` carries an `authored_by` identity and a short message, and every prior revision is retained in-substrate. There is no parallel audit table, no `/history/` subfolder, no filename-encoded versioning. This completes Axiom 1 (content-addressed retention + parent-pointer history) and operationalizes Axiom 2 (every file has an author, enforceable at the write path). See ADR-209 and [authored-substrate.md](authored-substrate.md).

14. **Chat is the source of truth for work; standing declarations are legibility wrappers** — Per Axiom 9, every invocation emits a narrative entry, and the narrative is the operator-facing log of *everything* the system did. `/chat` is the narrative surface, not a chat feature; a standing declaration's runs are the narrative filtered to its kept file, not a parallel log. An attended turn and a standing run share one atom (the invocation); the declaration differs only in carrying a schedule + a contract that labels and schedules future invocations. This principle gates design decisions: any proposal that sketches a "separate log" for a category of system activity (standing-work runs, witness verdicts, MCP calls, captures) is a candidate for absorption into the narrative with a rendering-weight decision, not a storage decision. See [invocation-and-narrative.md](previous_versions/invocation-and-narrative.md) for the full framing.

15. **Agent seats persist; occupants rotate** *(retired — the review seat was deleted by ADR-632; the surviving form is the app↔resident registration, ADR-467/601. Record: previous_versions/FOUNDATIONS-v9.20-2026-09-12.md.)*

17. **The acting principal is the runtime principal; autonomy is the witness dial** (ADR-249, generalized by ADR-373/405/408) — The workspace has **N accountable human principals** (members, their AI connections, agents under grants), and each acts through embodiments — the shell, a lane, an external LLM over the interop face — that are all *that principal*. Permission comes from the grant (who may act where); **autonomy is witness timing** (ADR-405 — which consequential beats surface before they bind: `manual` = every one; `bounded` = above the declared ceiling; `autonomous` = within the pre-declared envelope), and no rule keys on the principal's species or role enum. The human can always intervene. **The owner remains the constitutional author** (ADR-386 D4). The seat-era form of this principle — one operator with two embodiments, one of them an AI Reviewer running a Loop in the human's absence — is retired with the seat (ADR-632); nothing acts in a member's absence except their own standing declaration.

16. **YARNNN is an Agent-Native Operating System** — The architectural framing is literal, not metaphorical. The substrate (filesystem + primitives + axioms + privileged daemons) is the **kernel**. The primitive matrix is the **syscall ABI** — userspace's only invokable boundary. The YARNNN chat agent is the **shell** (application code that uses the kernel like any other application — ADR-205 already honored this); per ADR-407 D2 (2026-07-06) the workspace has **one filesystem and N shells** — each member's shell *instance* (windows, drawer, read cursors) is member-experience scope, while the compositor's inputs (SURFACES overlay, program declaration) remain workspace scope. Workspaces are **userspaces** (operator-owned per-instance state). Programs (alpha-trader and any future activated programs) are **applications** that run in userspace; their bundle (`docs/programs/{program}/`) is the equivalent of an `.app` bundle — declarative manifest + reference data + composition manifest. The **compositor** is the FE/API infrastructure that resolves a program's composition manifest against substrate paths to render the cockpit; it sits between kernel and program, reading both, authoring neither. The **system component library** (`web/components/library/`) is the equivalent of shared system libraries — universal building blocks programs reference declaratively. This principle locks the kernel boundary: kernel changes are sacred and require review against all reference programs; programs do not modify the kernel; the shell is application code; the compositor reads but never authors; system components are additive-only; program bundles are versioned in-repo. Adding a program is purely additive — a new bundle, possibly new system component library entries, no kernel touch. This principle dissolves the "workspace type / workspace mode" naming question: workspaces don't have types; they run programs; the program declaration is the implicit type; specialization happens at the compositor, not the kernel. Ratified by [ADR-222](../adr/ADR-222-agent-native-operating-system-framing.md). Implementation roadmap: [os-framing-implementation-roadmap.md](os-framing-implementation-roadmap.md).

18. **Standing intent implies Trigger-authoring authority** *(retired — ADR-603 D5 / ADR-632: the Trigger dimension is authored by a member's standing declaration, never by an agent, and the kernel has no cron an agent tunes. Record: previous_versions/FOUNDATIONS-v9.20-2026-09-12.md.)*

20. **Wake is the irreducible architectural unit; the funnel is the singular evaluation mechanism** *(retired — ADR-632 deleted the wake sources, the funnel and the gateway; Axiom 4 now names the two trigger shapes. Record: previous_versions/FOUNDATIONS-v9.20-2026-09-12.md.)*

19. **The kernel does not compute for the prompt** (2026-05-15, ADR-281) — The lane frame reads substrate; it does not derive new state at prompt-assembly time. Any computation that produces state-shaped data (summary, aggregation, compaction, projection) must write its result to substrate first; the envelope reads that substrate like every other substrate file. Per-turn prompt-time computation that produces state without writing it to substrate is an Axiom 1 violation (substrate-as-bus, fourth sub-clause). **Diagnostic test**: if a kernel function takes substrate inputs and produces a string that goes directly into an LLM prompt without first being written to substrate, the function violates this principle. The fix is always the same shape: move the computation to a mechanical primitive; have it write the result to substrate; let the envelope read the substrate file. **Mechanism**: the substrate-mirror pattern from ADR-264 (`SyncPlatformState` for external state) generalizes to derivative-compaction state — a standing declaration or a capture writes derivative substrate at known cadence. Derivative-compaction substrate has the same canonical-home discipline as external-mirror substrate: written by a named primitive, attributed via ADR-209, retained in the revision chain, read by the envelope as a normal `path` entry. **Architectural counterpart**: this principle is YARNNN's structural alignment with Claude Code's substrate-access model — `Read` returns substrate content unchanged; the kernel does not pre-aggregate, summarize, or derive on the model's behalf at prompt-assembly time. YARNNN's additions (Authored Substrate, personification, substrate-canonical world) sharpen the model; this principle ensures we don't diverge from its substrate-access shape. See [ADR-281](../adr/ADR-281-substrate-canonical-substrate-only-prompts.md).

23. **One gate, one queue: consequential actions gate on Mechanism; reads and narration do not** (2026-05-30, ADR-307) — A *consequential* action — any primitive that mutates substrate or has external effect — passes a single uniform permission gate (the Mechanism dimension), resolved at one chokepoint (`execute_primitive`), never re-implemented per primitive. The gate resolves **apply / queue / deny** from the autonomy mode × the primitive's `read_only` declaration (fail-closed: unlisted = consequential) × the action's governance class × operator-declared locks. **Reads and narration are not consequential and never gate** — they observe substrate or emit narrative, mutating nothing the operator must pre-approve. When the gate says *queue*, the action waits in the **single operator-approval queue** (`action_proposals`, the Channel surface per Derived Principle 12) until the operator approves — because an unattended run has no one to pause for, and an agent under a bounded grant may not bind a consequence the member has not witnessed (the deliberate divergence from Claude Code's synchronous-pause model, which fails closed when no human is present). The queue is *generic*: keyed on `(primitive, inputs)` with family-shaped `decision_context` (capital → rationale/expected_effect/reversibility; substrate → diff/message); the cockpit renders by family. **Diagnostic test**: if a primitive gates itself (autonomy logic inside the handler) rather than at `execute_primitive`, or if a "wait" outcome hard-errors instead of queuing, or if a consequential primitive bypasses the gate entirely, it violates this principle. **Composes with** Derived Principle 12 (Channel legibility — the queue is the legible Channel for gated actions), the ADR-293 governance/operational substrate taxonomy (the `deny` tier = governance lock; bypass-immune), and ADR-249 (autonomy = approval-degree, now uniform across all consequential primitives). **Canon source**: [ADR-307](../adr/ADR-307-unified-permission-taxonomy.md) + the Claude-Code permission-architecture cross-check (`docs/analysis/src_claudeCC/`).

22. **The system prompt carries only the participant contract** (2026-05-29, ADR-306; re-cut for the lane frame 2026-09-07) — What makes an agent in a YARNNN lane different from a generic assistant — it works *inside a shared, attributed commons*, under *a member's grant*, with *craft the member can read* — is carried by **substrate + code + skills**, not by system prose. The system-authored frame (`build_lane_conventions` in `api/services/lane_runner.py`) carries only what is irreducibly the runtime's to say: the participant contract (`api/services/workspace_paths.py` — how the filesystem is told, how attribution works, how the agent addresses the member per ADR-638), the app's posture (`register_app(posture=…)`), the focus declaration, the reach paragraph, and an index of skills whose bodies load on demand. **The frame narrates no fundamental and re-teaches no substrate file** — that is the anti-rebloat constraint. Craft with a contract belongs in a skill (`api/services/skills/`, ADR-630); grammar is derived from the app registries; code-enforced gates (locks, the witness gate, budgets) carry no prose at all — the gate holds and the tool result reports it. **Diagnostic test**: every proposed addition to the frame must answer *"is this the runtime interface, or a shape the model has no prior for?"* — if neither, it belongs in substrate, a skill, or code. 26. **Operations run four flows; programs declare them; completeness is conformance (the Four-Flow Completeness Model)** (2026-06-10, ADR-332) — An operating workspace runs **four flows**: **context in** (perception — self-past via harvest, self-present via live reads + operator push, world-present via the perception field [arc-3, deferred]), **work out** (the acts — artifacts / transactions / messages), **outcomes in** (ground-truth intake — reality's verdict on the operation's *own* acts; the **coupling term** between self and world, which is why Axiom 8's substrate is the moat's spine; generalized by ADR-330), and **the loop** (calibration per ADR-327, which runs only where flow 3 exists). The felt "offness" of a generic workspace is **flow-incompleteness** — not UX, not ICP, not cold-start; those are symptoms. **A program IS a flow-declaration set**: what a bundle ships (oracle + `substrate_abi.ground_truth`, context domains + universe + standing declarations, capabilities, deliverable specs, persona, surfaces) is the four flows, declared — this is Direction A's positive account ("you cannot operate without a program" = "you cannot operate with undeclared flows"). Consequences: no default program; no freehand workspace-level flow declarations (flow slots are what *programs* declare; operator-assembled programs arrive, if ever, as assembling a *program*); ADR-331's `/setup` sequence is flow-declaration walking — the kernel's definition of becoming operational, rendered as a sequence. **Flow-completeness is bundle conformance**: every active program declares all four flows or explicitly marks a flow N/A with rationale (first instance: ADR-330 D4; general gate lands at arc-3 per ADR-287 discipline). **Perception discipline** (foundation fixed, build deferred to arc-3): *reality enters only as attributed observation; watches are declared, never crawled; transports are peripherals; attention is calibrated* — selection is judgment and cannot commoditize; transports (MCP et al.) are consumed as drivers, never built as a catalog; flow 4 judges *attention*, not just actions (the trader's `by_signal` expectancy attribution is the existing proof). **Relation to Axiom 2's perception layers** (external / user-contributed / internal / reflexive): the perception layers are the *source taxonomy*; the four flows are the *loop view* (directional completeness of one operation cycle); the two compose without conflict. **Diagnostic test**: when a workspace or program "feels partial," enumerate its four flows — the missing or undeclared flow is the diagnosis; the remedy is a declaration (bundle-side) or an intake/transport (kernel slot), **never a parallel subsystem** (Principle 7; the dual-tracking bright line: the substrate is the record). **Composes with** Principle 16 (programs as applications), Principle 25 (flows write into `operation/`), Axiom 8 (flow 3 fills its substrate), Principle 4 (distill-don't-mirror is why internal/reflexive outrank raw external). **Canon source**: [ADR-332](../adr/ADR-332-four-flow-completeness-model.md) + the 2026-06-10 capture chain it cites.

27. **Perception is the operation's epistemics under calibration (the Perception Field)** (2026-06-11, ADR-335) — Reading the world is commodity; the **declared / distilled / tenured / calibrated** perception field is the asset — the world-facing half of the cumulative substrate. Perception decomposes into three layers with distinct durability classes: **Declaration** (kernel, axiomatic — `substrate_abi.watches`, the perception twin of `substrate_abi.ground_truth`; selection is judgment and cannot commoditize), **Observation contract** (kernel, axiomatic — reality enters only as `{watch_id, source_ref, attestation, observed_at, distilled_content}` written to attributed signal substrate; reuses the Axiom 8 attestation enum verbatim, convention-first per ADR-335 §6), **Transport** (deliberately commodity — REST/RSS/CSV/MCP, a swappable driver class consumed from the ecosystem, never built as a catalog). **Watch-first, transport-second**: a transport enters the workspace only because a declared watch needs it — never "browse the marketplace and add interesting perception." Judgment is **substrate-aware and transport-blind** — attestation is the only property that crosses the transport boundary, as an observation property, never as device-awareness; a flaky transport is therefore a driver swap, never a redesign. **Transport trust is a derived tier, not a platform class** (2026-06-19, ADR-335 derived-trust-tier amendment) — the retired "head/tail split" was never a property of a platform but the *output* of `required_tier(read, program) = HIGH if the read feeds ground-truth or a primary action, else OPEN`; a binding is permitted iff its `attestation_grade` (the Axiom 8 enum, derived from provenance, **never stored as a tier** — Principle 7) meets the derived tier. Direct-API and an attested official MCP server both *can* carry `platform` grade; "head driver vs MCP" is two transports each carrying a grade, not two classes of platform — the gate reads the grade, never the protocol. Alpaca stays Direct API *by derivation* (it feeds money-truth ⇒ HIGH ⇒ `platform`-grade), money-truth-never-via-community-server now a theorem not a special case; the same read can be HIGH for one program and OPEN for another simultaneously. (Discharged by receipt 2026-06-18: GitHub's remote MCP server accepted standard OAuth Bearer through the in-kernel client; the ADR-076 ghost is dead.) **Connection vs watch** (Open Question A, closed NO 2026-06-18): a watch is a declaration in the aperture (DP24/ADR-343 §31), a connection is a transport below it; a watch *consumes* a connection (declare-watch → resolve-transport), it is not *made of* one — the two binding shapes (`watch_id` NULL = capability binding; set = watch binding) coexist permanently. **The cadence dial**: a harvest (ADR-331 Mode-A) and a standing watch are one observation contract distinguished only by Trigger shape (once vs. forever) — the perception instance of the inline-action → task gradient (Axiom 9 Clause C). The watch declaration is a portfolio of attention; flow 4 prunes it over tenure (the trader's `by_signal` expectancy attribution is the existing proof). **Diagnostic test**: a connector catalog, a source-freshness table, a "perception manager" subsystem, or raw foreign-tool output in substrate each violate this principle — the substrate is the record, and absence of observations is itself perceivable from the record (`observed_at` timestamps), so binding failures surface as evidence, never via transport introspection. **Composes with** Derived Principle 26 (this is flow 1's world-present cell, built), Axiom 8 (attestation enum + the ground-truth twin), Axiom 4 (cadence is Trigger; a watch is a member's standing declaration, ADR-603), Principle 7 (no dual tracking). **Canon source**: [ADR-335](../adr/ADR-335-perception-field.md) + [perception-under-calibration-arc3-foundation-2026-06-10.md](../analysis/perception-under-calibration-arc3-foundation-2026-06-10.md).

28. **The management plane: operating the operation is first-class product surface** (2026-06-11, ADR-338) — The four flows (Derived Principle 26) have an operator-facing projection that is not itself a flow: **the management plane** — the standing set of surfaces through which the operator *owns* the operation. Context-in projects as source/watch management; work-out as deliverable specs + preferences; outcomes-in as attestation, import, and verdicts; the loop as delegation dials, budget, and calibration reads. The product has two halves: the **operation** (kernel + program running unattended) and the **operationship** (the operator's standing practice of installing, granting, declaring, approving, tuning, reading) — and the second half is where trust is manufactured. This extends the literal OS framing (Derived Principle 16) to its **experience half**: programs are apps the operator *installs* (App Store + installer = catalog + activation flow-walk per ADR-331/244); transports are *drivers* the operator *binds* (connectors, watch sources, future MCP bindings); governance dials are *System Settings panes*; the Queue is the *permission dialog with the diff shown*; Files is *Finder*. A driver install got simpler over an OS's life but never invisible-without-consent — that is the design north star. **The consent line** is the discipline that prevents over-rotation into ceremony: acts that change *what the operation is allowed to do or perceive* (activate, bind, declare watches, grant delegation, set budget, approve a diff, attest an outcome) get first-class surface — compressing them into invisible automation destroys ownership and, per Derived Principle 12, caps the autonomy an operator will ever grant; acts that change *what the substrate currently says* within already-granted allowances (fork, fetch, distill, mirror, materialize) stay invisible automation under the revision chain. **Diagnostic test**: an operator-facing step proposed for "automation away" must first answer "is this a consent moment?" — if yes, the fix is a better surface, never a removed step. **Composes with** Axiom 6 (Channel — the plane is Channel-dimension projection, rendered by ADR-245's L1/L2/L3 model, no new architectural layer), Derived Principle 12 (legibility gates autonomy), Derived Principle 16 (OS framing, now both halves), Derived Principle 26 (the flows it projects). **Canon source**: [ADR-338](../adr/ADR-338-management-plane.md) + the 2026-06-11 journey-week evidence it cites (every operator act ran through the developer harness because the cockpit surface was thin — the empirical trigger).

29. **Mirror once, compose few (the operator experience model)** (2026-06-12, ADR-340) — The surface census has two classes. **Mirror surfaces**: one surface ↔ one substrate concern — complete, neutral, faithful, the experience-level escape hatch (ADR-297's discipline; the `/proc` of the OS). **Composition surfaces**: one surface ↔ one operator-**act** — selective, opinionated, program-weighted, synthesized over many substrates (ADR-312's Home contract, generalized). Every substrate concern earns exactly one mirror; the operator experience is carried by a small fixed set of act-shaped compositions, one per act of the **operator's standing loop** — Decide · Read · Dwell · Tune · Amend · Setup — which is *derived* from the four flows (Derived Principle 26) × the consent line (Derived Principle 28), never from a persona: the content of each act is program-specific, the shape is kernel (the macOS resolution to unbounded user-shapes — the OS commits to few universal acts; apps carry the use-cases). **Compositions foreground; mirrors are reachable from compositions, never the default** — this is ADR-245's L1/L3 discipline lifted from the file level to the experience level (a launcher that foregrounds mirrors is L1-weighted at the experience level, a design error). **Attention-routing is an OS responsibility, not a destination**: what demands the operator now is *derived* from substrate — pending `action_proposals`, the narrative weight taxonomy (material/routine/housekeeping), budget runway — and **never stored** (a `notifications` table is the ADR-153 shape of mistake); it travels three channels (badges/vitals · attention center · in-the-moment dialogs), so mirrors stop being attention destinations and the operator arrives at the Queue by routing, not by remembering. **Diagnostic test**: a new launcher-level surface must name which act it composes or which single substrate concern it mirrors; 31. **A citation binds a claim to its Source, never to the internal path; attribution is orthogonal** (2026-06-22, ADR-357) — Three concepts that get conflated are distinct and must stay distinct: **Source** (where content came from *in the world* — a repo path, a URL, a channel id: the `source_ref` of the observation that grounded it, per Derived Principle 27 / the Observation contract), **Attribution** (who *in YARNNN* wrote the substrate — `authored_by`, per Axiom 1's authored-substrate clause / ADR-209), and the **internal filesystem path** (where the distilled copy happens to live — plumbing). A **citation** in any authored artifact binds a claim to its **Source**; it is never the internal path (the reader cannot verify a claim against `/workspace/operation/authored/_repo_signal.yaml` — that is where *this operation* filed its copy, not where the truth lives) and never `authored_by` (who typed it is not where it came from). **This is the authoring/output twin of Derived Principle 27**: DP27 fixes how reality *enters* (only as `{source_ref, attestation, observed_at, distilled_content}`); this fixes how a claim grounded in that reality *exits* (citing the `source_ref` the observation carried). The two concepts already exist in canon — `source_ref` (DP27) and `authored_by` (ADR-209); this principle names the binding rule that keeps them from tangling at authoring time, and adds the floor: **a claim with no resolvable Source does not ship** (the perception-field instance of the anti-confabulation rule — you may not assert what you cannot point at). **Where it lands** (per agent-composition.md §3.2.1): the *interface-grammar* (cite the Source, not the path; attribution is separate) is **frame-resident** — one clause in the persona-frame action-grammar, the same category as "cite what drove your verdict" (it makes provenance legible, it is not a rule of judgment); the per-program *sourcing rule* ("a number/claim that cannot be traced to a Source does not ship") lives in `principles.md` / the bundle authoring spec, replacing any "trace to a workspace file" phrasing (which encodes the exact internal-path confusion this principle forbids). **Diagnostic test**: an authored piece that cites "ADR-354" as a bare name (no resolvable path), or that points a citation at the internal signal file it read from, or that conflates `authored_by` with the source — each violates this principle; a piece that cites `Kvkthecreator/yarnnnn/docs/adr/ADR-354-….md (observed 2026-06-22T07:05Z)` honors it. **Composes with** Derived Principle 27 (the Source it cites is the observation's `source_ref`), Axiom 1's authored-substrate clause (the attribution it stays distinct from), Derived Principle 23/25 (the no-unsourced-claim floor is the consequential-output gate's authoring instance), and the anti-confabulation action-grammar (you may not narrate — or cite — what no observation produced). **Canon source**: [ADR-357](../adr/ADR-357-citation-binds-to-source-not-internal-path.md) + the 2026-06-22 citation-verification of the first repo-watch-authored piece (every cited receipt traced to perceived substrate; the gap was *form*, not honesty).

32. **The ledger-intake invariant: raw observation in, derived citing act out, raw never rewritten** (2026-06-26, ADR-376) — Every contribution to the substrate enters as an **attributed raw observation**; what the workspace *makes* of it is a **separate, attributed, derived act**; the raw is **never rewritten** and the derived **always cites its source**. This is **how context enters the kernel at large** — system-wide across all context-in transports (MCP saves (the `remember` verb at authoring time; file-native `save` since ADR-543), platform connectors, human uploads, the perception field's web/RSS watches, ground-truth intake, chat, A2A), not an MCP-layer concern. It is the **retention/separation invariant** the ledger (the authored-substrate floor — Principle 13) did not yet carry: git's uncopied property is that *a commit never silently overwrites what it records* — the raw object is immutable, derived state (a merge, a working tree) is a separate object pointing back. The authored-substrate clause gave the ledger content-addressing + parent-pointer history + attribution; this principle adds the one missing piece — **the raw observation persists as its own object, distinct from the understanding derived from it** — which is what turns the moat's headline (*which principal contributed each version, and how the seat reconciled them*) from **approximately** legible (in-place edit history) to **structurally** legible (raw contributor-object → derived seat-object, walked by a structured `derived_from` citation). **The substrate twin of the multi-principal model**: the per-principal authorization model collapses "personal vs team" into *one model, the principal count is data*; this collapses "MCP vs connector vs upload" into *one intake model, the source is data* — every transport is a principal writing a raw observation, processed by one derive step. **The invariant is `retain + attribute + cite`, not a mechanism**: structured attested intake (Axiom 8 outcomes) keeps its raw as event-rows folded into a regenerated summary; unstructured contribution (MCP/uploads/web/A2A) keeps its raw as immutable files in a **raw lane** — `inbound/{transport}/{principal}/…` (machine/external), sibling to the human `uploads/` root (both outside the constitution/operation/governance topology cut per Derived Principle 25, both reasoned-against-never-rewritten — `uploads/` is the N=human case of the same shape). The derive step writes the understanding into `operation/` (or the program's structured tree), authored by the seat/deriver, carrying a structured `derived_from: <raw path/revision-id>` so `trace` walks raw↔derived mechanically. Perception retains the observations a derived act **cites** (the evidence behind a judgment), never every fetched byte (the raw lane is evidence, not a crawl archive). **The audit that proves it is load-bearing**: of the four substrate-writing intake paths, two already obey it and are clean (`uploads/`, ADR-330 ground-truth) and two violate it with the predicted symptoms — MCP `remember` **conflates** (the placement wake rewrites the dump in place, demoting the foreign origin to a parent-pointer) and the web/RSS watch **discards** (only the distilled signal is kept, so a signal's driving observation is unrecoverable and the watch is unfalsifiable); both are fixed by the same rule. `operation/memory/{slug}.md` is the concrete casualty — one namespace doing two jobs (raw inbox **and** derived home), which is *why* placement must rewrite in place; conformance routes its raw to the `inbound/` lane and makes placement a derive-and-cite. **The dull-rule dividend** (the savings the simplicity produces): no merge/CRDT (raw lanes are per-principal, single-writer — Principle 7 / ADR-286), no new authorization vocabulary (per-principal grant already governs who-writes-which-raw-sublane), no format engine (a rule that doesn't care what's entering cannot generate format-specific machinery — the "variety of formats" problem *dissolves*). **Diagnostic test**: an intake path that rewrites the contributor's raw in place, that discards the observation a derived act relied on, or that lets a derived `operation/` file omit its `derived_from` citation — each violates this principle; the fix is always the same shape (land raw immutably + attributed, derive separately + citing). **This is the authoring/output triad's input member**: Derived Principle 27 fixes how reality *enters* (form), Derived Principle 31 fixes how a claim *exits* (citing its Source), and this fixes how the entered observation is *retained and transformed* (raw kept, understanding derived-and-citing) — the three close the perception→substrate→authoring loop. **Composes with** Axiom 1's eighth sub-clause (the form-contract this completes) + ninth sub-clause (its substrate statement), Principle 13 (the authored-substrate floor it extends), Derived Principle 25 (the topology the raw lane sits in), Derived Principle 26 (it is the cleanest formalization of flow-1 context-in), Axiom 8 / ADR-330 (the outcome-attestation discipline it generalizes), and the multi-principal re-key (its sibling axiom — per-observation intake ‖ per-principal authorization). For any **non-text** raw, the derive step this principle *permits* is **mandated** by Derived Principle 34 (a model reads only a projection {text|image}, never the container) — retention alone never yields a consumable object; the projection is the derive act, carrying the same `derived_from` citation. **Canon source**: [ADR-376](../adr/ADR-376-ledger-intake-raw-observation-vs-derived-substrate.md) + [the-ledger-intake-axiom analysis](../analysis/the-ledger-intake-axiom-raw-observation-vs-derived-substrate-2026-06-26.md).

33. **Collapse the category into data; layer what remains (the re-founding's unifying operation)** (2026-06-29, the re-founding keystone) — One operation produced the architecture's whole macro shape, applied four times: **collapse a category that was being encoded as *structure* into *data*, and carry what remains on the right layer.** (1) **Intake** (ADR-376) — "MCP vs connector vs upload vs web" collapses: *the source is data* (an attribution), and raw-vs-derived stops being a *namespace* (`inbound/`) and becomes a *revision-kind* (Axiom 1 ninth sub-clause amendment). (2) **Principals** (ADR-373) — "personal vs team" collapses: *the principal count is data* (N=1 is the singleton case), and who-may-write stops being a class-fixed prefix policy and becomes a *per-principal grant on the file*. (3) **Agents** (ADR-596/600) — "one fused Reviewer" collapses: *the agent count is data* (one register, N agents), each an *attribution identity* whose authority lives on grants rather than on the agent, not a subtree. (4) **Filesystem** (this re-founding) — "kernel-class roots vs work folders" collapses *for the commons*: *meaning is the only namespace organizer*, and permission/provenance move to *metadata on files and revisions* (defaulted-by-meaning, owned-by-grant — the seventh sub-clause amendment; minimized Derived Principle 25). **The result is one ledger carrying everything the kernel needs** — content + history + attribution + permission + provenance-kind + citation — while the namespace carries only **meaning + the minimal path-anchored residue** (the kernel-read grant/floor/`system/` + the principal-homes). This is **Axiom 1's fourth sub-clause (`substrate IS the bus`) taken toward completion**: every kernel concern rides the revision; nothing rides the path except meaning and the irreducible bootstrap floor. **The coherence proof**: the four decisions are not four philosophies that happen to agree — they are *one operation at four scales*, which is why the macro vision is hardened (a reviewer finds one principle + four instances, not four to reconcile). **The diagnostic test**: a proposed mechanism that encodes a *kind-of-thing* (which transport, which principal-class, which agent, which permission-class) as a *place in the namespace* — rather than as a field on a file or revision — is very likely re-introducing the category error this principle dissolves; the fix is the same shape every time (move the category to data, keep the namespace for meaning), *except* where the kernel must read a fixed path to bootstrap its own authority (the grant/floor residue — the one place structure is irreducible). **Composes with** Axiom 1 (the sixth/seventh/ninth sub-clause amendments are its three filesystem instances), Derived Principle 25 (minimized by it), Derived Principle 32 (its intake instance), ADR-373 (its principal instance), ADR-596/600 (its agent instance), ADR-378 (the topology ceiling it operates *inside* — federation, the one axis above the workspace, is where the "single-substrate" condition the relaxation rests on would re-open). **Canon source**: [the re-founding keystone](../analysis/the-re-founding-meaning-folders-and-permission-as-metadata-2026-06-29.md) + the triple-check findings (analysis note, since removed) (REVISE-FIRST → the corrected, ratifiable statement).

34. **The model-consumable projection: substrate crosses into a model only as text or image, never as the raw container** (2026-07-01, ADR-395) — A substrate object is delivered to a language model **only as a model-consumable projection — text, or image** (audio for audio-native models). The **raw container is retained** (Derived Principle 32 — immutable, attributed) but is **never itself the thing read**: consumption requires projection, because a model reads text and images and *not* arbitrary file formats. This is a **fact of the medium, not of YARNNN** — it holds through MCP (a `CallToolResult` reliably carries only `text`/`image`/`audio` content; a `resource_link` URI is host-discretionary and auth-blind, never a guarantee) *and* through the direct model API (even the most file-native vendor converts docx/xlsx/pptx to text/PDF before the model reads). The projection is a **derived, attributed act that cites the raw** (Derived Principle 32's derive step — here made **protocol-mandatory** for any non-text raw, not merely permitted): retention alone never yields a consumable object. **Format variety is contained in a swappable derive-registry** — one strategy per format-family (the intake mirror of the output gateway `render/skills/`, running blob→{text|image} where the gateway runs text→{pptx,xlsx,pdf}); a format with **no registered strategy is retained-but-not-yet-consumable — legibly marked, never silently dropped or fabricated** (the anti-silent-drop clause + the graceful-degradation path that makes "any format at large" safe: an unhandled format is a *known gap*, not a break). A raw-container **reference over interop** (`resource_link`/embedded blob) is a **best-effort enhancement for hosts that provably fetch-and-auth it** (host-profile-gated, ADR-379) — **never a substitute** for the text projection the model is guaranteed to read. **This is the consumption member of the perception cycle**: Derived Principle 27 fixes how reality *enters* (input), Derived Principle 32 fixes how the observation is *retained* (retention), Derived Principle 31 fixes how a claim *exits* citing its Source (output-binding), and **this fixes how the retained object is *delivered to the model that reads it*** (consumption) — the four close the perceive→retain→consume→cite loop. **The dull-rule dividend**: the kernel stays **format-blind** (it says only "consumption = projection"; all format-specific machinery lives in the service-layer registry, additive per format-family); no schema change (blobs already storable via `content_url`); no new authorization vocabulary. **Diagnostic test**: a path that hands a model the raw bytes of a non-text/non-image container and assumes it is read; a path that returns a `resource_link` to an authed blob and treats it as delivered; a derive step whose projection omits its `derived_from` citation to the raw; or an unhandled format that is silently dropped rather than marked retained-not-consumable — each violates this principle. **Composes with** Derived Principle 32 (its retain half; this is its consume half — the derive step DP32 permits, this makes protocol-mandatory), Derived Principle 27 + 31 (the input + output-binding members of the same cycle), Axiom 6 (Channel — egress is a Channel act; the medium's text/image constraint is a Channel invariant), ADR-379 (the host-profile gate the raw-reference enhancement rides), ADR-393 (the mechanical capture lane the derive step registers in), ADR-394 (the connector instance of the same retain-then-project pattern). **Canon source**: [ADR-395](../adr/ADR-395-model-consumable-projection-and-upload-intake-conformance.md) + [the model-consumable-projection analysis](../analysis/the-model-consumable-projection-axiom-2026-07-01.md) + MCP spec 2025-06-18 + Anthropic Files/PDF platform docs.

35. **The three-scope taxonomy + the viewer parameter: every persistent store declares its scope; the viewer is a parameter, never a fork** (2026-07-06, ADR-407 + ADR-408 + ADR-410 + ADR-412) — Every persistent store declares exactly one of three scopes: **workspace content** (keyed `workspace_id` — the commons: substrate + revisions, the three act ledgers, grants, the witness queue, balance; what every member reads identically), **member experience** (keyed `(workspace_id, principal_id)` — one member's private operating state: chat sessions + lanes, shell/window state, read cursors — the `member_state` store; **never consulted for authorization and never holding authored content** — the two invariants that keep it from becoming a shadow substrate), and **account** (keyed `user_id` — the human across workspaces: credentials, billing identity, theme). ADR-407 §3 is the living scope registry; a new store that cannot name its scope is a design error. **The interaction model is macOS, not Figma** (ADR-407 D2): N first-person shells over one shared filesystem — freshness is pull, conflict surfaces at save (ADR-406 CAS with the intervening principal's attribution), continuous cross-client view-sync is a non-goal. **The viewer parameter** (ADR-412 D6): the one commons renders **first-person per viewer**, and the rendering differences are *derivations over shared substrate, never forked surfaces or stored per-viewer copies* — (a) *attribution* resolves "You" vs the peer's name from the acting principal's identity on the ledger row (ADR-410 D6 `author_identity_uuid`/`actor_id`; ADR-405 D4 — self-witness is trivially satisfied, so the bell excludes the viewer's own acts by construction); (b) *attention* is **one derivation, N mounts** (ADR-410): "what wants me" = the witness queue, "what happened" = the workspace timeline filtered per viewer — bell = glance, Notifications = workbench, Home slot = ambient, three depths one source, with the per-viewer read cursor living in member-experience scope (DP29's derived-never-stored, completed per-viewer); (c) *affordances* render per the viewer's **grant coverage** (the resolved `write_regions` of their grant) — **never a role enum** — the UI twin of ADR-405's no-species-law; reads stay universal, FE gating is legibility, the server gate (DP23) is enforcement. A fresh member lands on the same Home rendered honestly; **there is no member-shaped surface set, ever** — the viewer is a parameter of rendering, never a fork of composition. **Diagnostic test**: a store keyed by `user_id` that members must share (the pre-ADR-407 balance gate); member-experience state consulted by the permission gate; an affordance keyed on `role ===`; a second attention store (in-app notification rows duplicating the ledgers — the ADR-407-Phase-2 shape ADR-410 D3 retired); a member-specific launcher/Home composition — each violates this principle. **Composes with** Derived Principle 17 (its principal half — N principals, each acting through embodiments), Derived Principle 29 (attention derived-never-stored — this is its per-viewer completion), Derived Principle 25/23 (the grants + the gate that affordance-coverage derives from and defers to), Derived Principle 16 (one filesystem, N shells), ADR-373 (the re-key whose read/experience half this taxonomy completes). **Canon source**: [ADR-407](../adr/ADR-407-the-three-scope-taxonomy.md) (+ the 2026-07-05 multi-user scope audit) + [ADR-412](../adr/ADR-412-three-altitudes-three-chromes.md) D6 + [ADR-410](../adr/ADR-410-attention-derives-from-the-timeline.md).

36. **Grants govern reach; share executes; export crosses** (2026-08-04, ADR-517) — **Who may reach what is a grant** — workspace-scoped (Axiom: the workspace is the outermost unit, ADR-378), narrowed per-grant along path-prefix axes (`read_scopes`/`write_scopes`, the powerbox), species-blind (ADR-405 — a human member, a viewer, and a connected AI differ in *technical handling*, never in the *kind* of authorization fact; `principal_grants` is the one table). **Mutating grants is governance** — minting, narrowing, revoking, and inviting all mutate who may act, so they all sit behind governance gates; share is not a feature beside the model but **the reflexive verb of governance** (the one act that writes to the grant table itself), which is why there is *no separate share policy* — the pre-ADR-517 free-for-all (any grant holder mints a workspace-wide member link) was the escalation this principle closes. **The enforcement contract is two-layer by ruling** (ADR-517 R1): the database guarantees *membership and the role-binary* (RLS write policies exclude `viewer`-role grants — the DB sees the shape it enforces, which is why the role is stored honestly rather than as axes-only narrowing); the primitive layer guarantees *path-prefix narrowing*; any code path that reads substrate on the user-scoped client without the primitive filters gets membership-truth, not scope-truth, and must say so at the call site. **Export is categorically outside the model**: share changes who can reach (in-system, attributed, revocable — authorization); export changes where the bytes are (out-of-system, attribution stripped, irreversible — governed by *honesty*, the declared-omissions manifest, because prevention is impossible past read access). **Diagnostic test**: a mint/revoke/invite path not behind a governance gate; a role or narrowing that exists only where RLS cannot see it; a proposed per-file ACL or visibility *attribute* (publicness is **derivable** — a file is public iff a live capability link covers it — never stored, or two sources of truth drift); a "share policy" system parallel to the grant table. **Composes with** Derived Principle 25 (defaulted-by-meaning, owned-by-grant — the file-side half of the same fact), Derived Principle 35 (affordances render per grant coverage, never a role enum — display; this principle is enforcement), Axiom 2 (identity/attribution — who acted; this governs who *may*), ADR-373/386/431 (the grant lineage). **Canon source**: [ADR-517](../adr/ADR-517-grants-govern-share-executes.md) + [grants-and-reach.md](grants-and-reach.md) (the singular reference — the roles, the axes, the mint/revoke authority table, the enforcement contract).

## Open Questions

Carried forward from v5.1, updated for v6.0:

1. **Agent evolution mechanics** — When an agent's domain expands (a Slack digest agent starts also monitoring email threads from the same team), does it become a new agent or does the existing agent's scope expand? Who decides? (Identity dimension — specifically, how Identity's scope mutates over time.)

2. **Surface composition at scale** — ADR-198's five archetypes map to four nav tabs. As operator workflows mature, does a sixth archetype emerge (e.g., Alerts as distinct from Queue)? How does the nav structure absorb this without fragmenting Channel? (Channel dimension, scale question.)

3. **Mechanism loosening rate** — Principle 11 says Mechanism loosens over time. What signal triggers the next loosening step (more agent autonomy within a task run, multi-round reasoning, filesystem browsing)? Grants and gates hold safety, but the *pacing* of loosening is open. (Mechanism dimension, direction of travel.)

4. **Multi-workspace for polymath operators** — ADR-191 commits to polymath-operator ICP. When an operator runs multiple businesses on one YARNNN account, is each a separate workspace or sub-scopes of one? How do the six dimensions behave under nesting? (Cross-cutting — Substrate nesting affects Identity, Purpose, Channel.)

5. **Display vs. Substrate-rendering boundary** — Principle 12 says autonomous writes need legible Channel. When a surface renders a filesystem file, where does Substrate-read end and Channel begin? ADR-198's Invariant I2 (no surface embeds foreign substrate) is a first cut; real surface work will surface edge cases. (Channel dimension, boundary question.)
