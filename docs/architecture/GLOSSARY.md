## Purpose

One word, one concept, one layer.

This glossary is the single source of truth for YARNNN terminology. Every ADR, architecture document, prompt, surface string, and marketing artifact must use the terms defined here. Drift triggers a correction PR — this is not soft guidance.

The glossary exists because YARNNN operates across four layers of cognition (the product, the role palette, the authored workers, the independent judgment seat) and three kinds of readers (users, developers, investors). Without discipline, the same word collapses layers and confuses readers. With discipline, every term lands on exactly one thing at exactly one layer.

One upstream discipline governs everything here: **semantic content lives in the filesystem** (FOUNDATIONS Axiom 1, the Substrate dimension). When a glossary term names a "ledger," a "policy," a "log," or any accumulated object, its definition must name the file path — not a DB table. Drift from file-native terminology is drift from the architecture, and both get corrected together.

## Operating System Framing (ADR-222, FOUNDATIONS Principle 16)

YARNNN is canonized as an agent-native operating system. The framing is literal — every box in OS architecture has a corresponding YARNNN artifact. The vocabulary below is canonical and replaces the would-have-been "workspace type / workspace mode" naming.

| Term | Meaning | Note |
|---|---|---|
| **Kernel** *(informal-canonical)* | The substrate layer: filesystem + primitives + axioms + privileged daemons. Domain-agnostic by construction. Equivalent to OS kernel. | Used informally alongside "substrate" (technical-canonical). "Kernel" is the macro frame; "substrate" is the technical implementation. Both valid. |
| **Syscall ABI** *(informal)* / **Primitive matrix** *(canonical)* | The set of typed verbs userspace can invoke against the kernel — the only entry point into substrate operations. Listed in `CHAT_PRIMITIVES` + `HEADLESS_PRIMITIVES` (ADR-168). | Same artifact, two framings. "Primitive matrix" is the technical name; "syscall ABI" is the OS-faithful framing. Both valid. |
| **Shell** *(informal)* | The interactive interface to the kernel — application code, not kernel. The YARNNN chat agent (`api/agents/yarnnn.py`). **ADR-407 D2 (2026-07-06): one filesystem, N shells** — each member's shell *instance* (windows, drawer, read cursors) is member-experience scope (`member_state` + per-(workspace, principal) keys); the compositor's inputs (SURFACES overlay, program declaration) remain workspace scope. | Per ADR-205, the shell is a regular `agents` table row using the same syscall surface as everything else. No privileged shortcuts. The N-shells model is macOS-not-Figma: pull freshness, CAS conflicts at save, no continuous view-sync (ADR-407 D2). |
| **Userspace** *(informal)* / **Workspace** *(canonical)* | The operator's `/workspace/` — a multi-principal attributed commons (ADR-373: one workspace = N principals — humans, agents, platforms, foreign/local LLMs — each attributed as itself), owned by its members, not by the kernel. **The workspace is the OUTERMOST unit YARNNN composes (ADR-378): one commons, served if-and-only-if an enterprise fits it; a second workspace is allowed but UNRELATED — cross-workspace federation (a shared agent, org hierarchy, cross-workspace grants) is explicitly undefined, the deliberately-unbuilt layer above the ceiling.** | Both terms valid. "Workspace" is the canonical project term; "userspace" is the OS-framing word. Workspaces are not "typed" — they run programs. The ceiling is a *positive definition* ("the workspace is the unit; federation undefined"), not a headcount cap ("one enterprise max"). |
| **Program** *(canonical)* | An application that runs in YARNNN userspace. Currently: alpha-trader (built), alpha-prediction (reference SPEC), alpha-defi (reference SPEC). **ADR-414 D5 (2026-07-07): activation is a *hire*** — the program installs an **Altitude-3 persona agent** into `agents/{slug}/` with its own file set; the activation record is a **grant row** (never the MANDATE prose marker, which is deleted vocabulary); the workspace is never typed or re-personed by it. | Equivalent to a desktop application. Programs declare what they need; the kernel doesn't know about them. See [docs/programs/](../programs/README.md). |
| **Program bundle** *(canonical)* | The declarative package shipping a program: manifest + reference workspace + composition manifest + dependencies. Lives at `docs/programs/{program}/`. | Equivalent to `.app` (macOS), `.deb` (Debian), `.apk` (Android). Versioned in-repo. |
| **Program manifest** *(canonical)* | The top-level declaration in a program bundle (currently `README.md` at bundle root). Names what the program is, what kernel features it depends on, what surfaces it commits to, success bar. | Equivalent to `Info.plist` (macOS), `AndroidManifest.xml` (Android), `manifest.json` (Chrome extensions). |
| **Composition manifest** *(canonical, format TBD)* | The bundle-shipped declarative spec for surface composition (`SURFACES.yaml` or equivalent — exact format defined by Program Bundle Specification ADR forthcoming). | Replaces would-have-been "workspace type" / "workspace mode." A program declares its surfaces; the compositor reads. |
| **Compositor** *(canonical, infra not yet built)* | The FE/API infrastructure that resolves a program's composition manifest against the operator's workspace substrate and renders the cockpit. Reads substrate; never authors. | New architectural layer named for the first time in ADR-222. Equivalent to a window manager / desktop environment compositor. Implementation ADR forthcoming. |
| **System component library** *(canonical, partial)* | The universal FE component library (`web/components/library/`) — building blocks composition manifests reference. | Equivalent to shared system libraries (libc, libGL). Additive-only; removing a component is breaking. Convention to be formalized in implementation ADR. |
| **Workspace overlay** *(canonical, infra not yet built)* | Operator-authored deltas to a program's composition manifest, lives at `/workspace/SURFACES.yaml`. Optional; defaults to program's manifest. | Equivalent to a user's customized DE preferences. Revision-tracked under Authored Substrate. |
| **Distribution** *(informal)* | A program understood as a curated bundle of (composition manifest + reference substrate + dependencies + commitments) on top of the YARNNN kernel. Same kernel; different program → different distribution. | Informal aid for positioning. Not a canonical technical term — programs and bundles are. |
| **Activation ladder / Rung 0·1·2** *(historical, ADR-380 — retired with the steward, ADR-632)* | The three activations of a workspace as the steward era counted them: Rung 0 the substrate wedge (file-native interop verbs + connectors + files), Rung 1 the steward present, Rung 2 a hired persona agent. With the steward deleted there is one activation: a workspace exists when its owner's grant does (ADR-373/465), and every agent is met through a lane under the member's grant. | Kept as a name the ADRs of 2026-06/07 use. |
| **Management plane** *(canonical, ADR-338)* | The operator-facing projection of the four flows: the standing set of surfaces through which the operator *owns* the operation — source/watch management (context-in), deliverable specs + preferences (work-out), attestation/import/verdicts (outcomes-in), delegation/budget/calibration dials (the loop). First-class product surface, never "setup overhead to automate away." | The OS framing's **experience half** (Derived Principle 28): the operation is the running system; the management plane is System Settings + Finder + the installer + the permission dialog. Channel-dimension projection rendered by ADR-245's L1/L2/L3 model — no new architectural layer. Governed by the **consent line** (below). |
| **Consent line** *(canonical, ADR-338)* | The discipline separating surface-worthy acts from invisible automation: acts that change *what the operation is allowed to do or perceive* (activate a program, bind a transport, declare watches, grant delegation, set budget, approve a diff, attest an outcome) get first-class surface; acts that change *what the substrate currently says* within granted allowances (fork, fetch, distill, mirror, materialize) stay invisible under the revision chain. | Prevents the management-plane reframe from rotting into ceremony: legible-and-owned, not laborious. A driver install got simpler over an OS's life but never invisible-without-consent. Per Derived Principle 12, hiding consent moments caps the autonomy an operator will ever grant. |
| **App Store / installer / drivers** *(informal-canonical, ADR-338)* | The experience-register names for management-plane surfaces: **App Store** = program catalog + activation (Settings→Workspace per ADR-244, `/setup` flow-walk per ADR-331); **installer** = the activation sequence surfacing a bundle's four-flow declaration before fork; **drivers** = transport bindings the operator grants (platform connectors, watch sources via `_sources.yaml`, future MCP bindings per ADR-335 Crawl-B). | Operator-ratified surviving vocabulary (2026-06-11). Pairs with the system-side rows above: kernel/programs (system half) ↔ App Store/drivers/Settings (experience half). |
| **Mirror surface** *(canonical, ADR-340)* | A surface fronting exactly one substrate concern — complete, neutral, faithful (files, activity, reach, standing work…). The experience-level escape hatch; the `/proc` of the OS. Every substrate concern earns exactly one mirror (ADR-297's discipline, named). | Mirrors are never deleted and never reworked into opinions — and they are **not the operator interface**: a launcher that foregrounds mirrors is L1-weighted at the experience level (ADR-245's L1/L3 lifted one level, Derived Principle 29). |
| **Composition surface** *(canonical, ADR-340)* | A surface fronting one operator-**act** — selective, opinionated, synthesized over many substrates, program-weighted under the ADR-312 contract (kernel owns the slots; programs weight/label/shape; kernel never invents a program noun). Home is the first instance; the act-set defines the full set. | Compositions foreground; mirrors are reachable from compositions, never the default. A mirror may *coincide* with an act (Queue↔Decide, Files↔artifacts) — coincidence is what earns a mirror primary placement. |
| **Standing loop (operator acts)** *(canonical, ADR-340)* | The operator's recurring act-set: **Decide** (consent moments) · **Read** (what happened) · **Dwell** (where it stands) · **Tune** (granted allowances) · **Amend** (constitution) · **Setup** (pass-through). Derived from the four flows × the consent line — never from a persona. | The macOS resolution to unbounded user-shapes: the OS commits to few universal acts; programs carry the use-cases. The act-shape is kernel; the act-content is program. |
| **Attention routing** *(canonical, ADR-340)* | The OS responsibility of bringing demand to the operator — **derived from substrate, never stored** (pending `action_proposals` + narrative weight taxonomy + budget runway; a `notifications` table is the ADR-153 shape of mistake). Three channels: badges/menu-bar vitals (state-at-a-glance), the **attention center** (top-bar aggregation, pure deep-links, no content of its own), in-the-moment dialogs (operator present). **ADR-410 (2026-07-06) makes the derivation singular + per-viewer**: two questions, two sources — "what wants me" = the witness queue (`action_proposals`), "what happened" = the workspace timeline (the three attributed ledgers) filtered per viewer (self-acts excluded at the bell per ADR-405 D4). Bell = glance, Notifications = workbench, Home slot = ambient — three depths, one source. | Consequence: mirrors stop being attention destinations — the operator arrives at the Queue by routing, not by remembering. Distinct chrome roles: the status cluster is Control Center (standing state); the attention center is Notification Center (events). The chat-narrative-derived activity feed is retired (ADR-410 §1 — post-ADR-407 the chat thread is the viewer's private session). |
| **Mention** *(canonical, ADR-492 D3 / ADR-605 / ADR-637)* | One species-blind addressing gesture (`@handle`, parsed by the ONE grammar in `services/addressing.py`) with two consequences: **@agent routes a TURN** (the mention IS the human act that fires it — never-ambient holds; ADR-495 D3) and **@person routes ATTENTION** (the mention fact is stamped on the message row at write time, derived per viewer into their To-do — ONE read cursor decides membership and VISITING the conversation advances it (ADR-637; the badge is recency over the same rows) — and dial-gated onto email via `send_notification(kind="mentions")`; ADR-605). | Not species law: the mount follows how the recipient attends (an agent attends only during invocation; a human attends when away). No `@everyone` (Activity already gives workspace-wide awareness for free); no tags-as-routing (the ADR-405 D5 subscription matrix, banned); mentioning a non-participant never auto-invites (disclosure is an explicit invite + visibility window, ADR-495 D2). |
| **Invocation contract** *(canonical, ADR-413)* | The kernel-invariant layer every external-engine invocation satisfies, regardless of protocol or engine: acts under a **principal + grant + gate** (DP23), consumes inputs only as **DP34 projections**, produces outputs only as **attributed revisions**, and meters on the **one ledger** (a rate-row exists before an engine is invokable). DP34's Mechanism-dimension sibling: DP34 fixes what crosses *into* a model; this fixes what any invocation *is* to the kernel. | Layer ① of ADR-413's four-layer stack (contract → drivers → catalog → intent vocabulary). Never code-forked per engine — the contract is what makes engines swappable data. |
| **Protocol driver** *(canonical, ADR-413)* | The ONLY code seam in the external-engine stack: one driver per **interaction protocol** — the physics/economics-derived classes (~4): **tool-loop engine** (LiteLLM is this class's driver), **async job** (the render service is the in-house precedent), **stateful session**, **sync query**. The Unix driver-class axiom applied outward: I/O discipline, never content type — modality is a *payload property* that dissolves at the engine level (ADR-413 v2's re-derivation; "language vs image capability" rejected as the seam). | ADR-335 made the same cut inbound (transports as peripherals, known by contract). Anti-goal: never force an async-job or session engine through the tool-loop protocol. New drivers are demand-gated, each its own ADR (ADR-413 D5). |
| **Engine catalog** *(canonical, ADR-413)* | Engines are **data, never code**: catalog rows carry the engine id, its protocol class (which driver serves it), payload tags (modalities — plural per engine), and its rate row (`_BILLING_RATES` — a rate-row-before-entry is the metering precondition). Generalizes ADR-402 (kernel model routing as data) + ADR-379 (host profiles) + ADR-411's `LANE_MODELS` whitelist. | Catalog unification is gated to the first non-tool-loop driver's ADR — until then the three registries stay separate (honest deferral, ADR-413). |
| **Intent vocabulary** *(canonical, ADR-413)* | Where the word "capability" survives: the UX-layer naming of what an operator can *ask for* ("draft an image", "transcribe this") — resolved to an engine + driver at invocation time. Never a code boundary, never a driver seam. | Layer ④. Engine choice is product law at Altitude 2 (recommend-never-conceal, the member picks); INVERSE for machinery (a system call's engine is kernel-chosen, ADR-556). |

**Retired vocabulary candidates** (rejected as housing for the specialization layer):

- **Workspace type / workspace kind** — rejected by ADR-222. Workspaces don't have types; they run programs. The kernel must not know about specific programs (kernels don't know applications). Type tags would have required kernel branches; the OS framing makes them unnecessary.
- **Workspace mode** — rejected by ADR-222. Implies switchability that doesn't exist (a trader workspace doesn't switch into a commerce workspace at runtime), and conflates Identity with Channel.

**Usage discipline:** when introducing a new mechanic that touches the architectural layering, name which layer it occupies (kernel / compositor / program-bundle / userspace / shell). A mechanic that crosses layers without justification is a design error per Derived Principle 16.

## Operation Rate, Output Contract & Witnessing (the operator's standing declarations)

> Every workspace is specified by four orthogonal operator declarations. Two are about *how the operation runs* (Rhythm, Witness dial), one is about *what it owes* (Expected Output), one is about *how it reasons* (Persona). The load-bearing discipline: **Rhythm and Expected Output are fundamentally different and must be captured separately** — a rate is not a deliverable, and neither derives from the other.

| Term | Meaning | Note |
|---|---|---|
| **Rhythm** *(canonical, ADR-327)* / **Heartbeat** *(informal)* | The operation's **rate of attention** — how often it wakes, reasons, and spends a judgment cycle. Declared as a spend envelope (`_budget.yaml`: `amount_usd × window`); tempo IS the spend (ADR-327: *"pace was always a budget wearing a frequency costume"*). Governance root — the operator declares it; standing work draws on it, never authors it. | Answers *"how often do I show up to work?"* The Trigger-dimension dial of the operator trifecta (Rhythm · Witness · Persona; ADR-298 D11). `_pace.yaml` retired (ADR-327) — there is no separate pace dial; spend-over-time is tempo. |
| **Expected Output** *(canonical, ADR-345)* | The operation's **output contract** — what it is on the hook to *produce*: the *kind* of artifact, the *delivery-cadence*, and the *bar*. The measurable half of the MANDATE (*why we exist*, made concrete). Declared as prose in `constitution/MANDATE.md` → `## Expected Output` (the operator's promise, survives occupant rotation) with a machine sidecar `_expected_output.yaml` the standing-obligation check (Derived Principle 30) reads. | Answers *"what am I on the hook to have produced?"* **Orthogonal to Rhythm** — a trader can wake every minute and correctly produce zero trades; an author can wake weekly and owe two essays a month; neither derives from the other. A **delivery-cadence + bar, floor-gated — never a hard volume quota** (a quota pressures the floor toward marginal output; a cadence the floor regulates). |
| **Witness dial** *(canonical reframe, ADR-345; mechanism ADR-307)* / **Autonomy** | The dial that selects **which consequential beats the operator witnesses before they bind** — NOT whether the agent works. The agent always works the full job (it is a judgment seat acting in absence); the dial routes attention. `autonomous` = the whole rhythm runs subconsciously (operator reads the trail at leisure); `bounded`/`manual` = chosen beats surface first (route to `action_proposals`). The Mechanism-dimension dial of the trifecta. | The mechanism is already this (`permission.py`: the gate runs *after* the agent acts; QUEUE = *acted-and-waits-for-witness*, never *blocked*). ADR-345 flips the **prose** from the prior "trust ceiling / approval degree" framing (which described the operator's permission-anxiety, not what the agent does). Resolves "does full autonomy mean zero operator approval?" → **yes: the agent works the whole job; the dial only decides what reaches the operator's attention.** |

**Usage discipline:** when a design surfaces a "should the operator decide X?" question, first ask whether X is a *witness* question (which the Witness dial answers — does this beat surface?) or a *contract* question (which Expected Output answers — what does the operation owe?). An agent that asks "what should I produce / on what cadence?" when Expected Output is undeclared is surfacing a **missing-contract symptom**, not correct consent-seeking (ADR-345; the 2026-06-18 author Path-A/B Clarify).

## The Three Scopes & The Viewer (ADR-407 + ADR-412 D6, FOUNDATIONS Derived Principle 35)

Every persistent store declares exactly one scope; ADR-407 §3 is the living scope registry. The viewer is a **parameter of rendering, never a fork of composition**.

| Term | Meaning | Note |
|---|---|---|
| **Workspace content** *(scope, canonical ADR-407)* | The commons — keyed `workspace_id`: substrate + revisions, the three act ledgers (`workspace_file_versions` / `execution_events` / `action_proposals`), grants, balance. Every member reads the same content. | The re-key ADR-373 started; ADR-407 Phases 0–5 completed the read/enforcement half. |
| **Member experience** *(scope, canonical ADR-407)* | One member's private operating state — keyed `(workspace_id, principal_id)`: chat sessions + lanes, shell/window state, read cursors. **Never consulted for authorization; never holds authored content** — the two invariants that keep it from becoming a shadow substrate. | Home: the `member_state` table (`GET/PUT /api/member-state/{key}`) + per-(workspace, user) localStorage keys as its cache (ADR-407 Phase 3). |
| **Account** *(scope, canonical ADR-407)* | The human across workspaces — keyed `user_id`: credentials, billing identity, theme. | The UserMenu "Account" window (ADR-347) is its surface. |
| **Member state** *(canonical, ADR-407 Phase 3)* | The server-backed member-experience store: `member_state(workspace_id, principal_id, key) → jsonb`, write-through from the shell (debounced, local-wins), newer-of reconciliation on mount. The attention read-cursor lives here. | Presentation state, not workspace state — DP29's derived-never-stored applies to the *content* of attention; the cursor is the one timestamp per (workspace, principal) it permits. |
| **Viewer parameter** *(canonical, ADR-412 D6)* | The rule that one commons renders **first-person per viewer** via derivation, never per-viewer copies or member-shaped surfaces: attribution resolves "You" vs the peer's name (`resolveActorForViewer` over the roster + ledger identity); attention derives per viewer (ADR-410: one derivation, N mounts — self-acts excluded at the bell per ADR-405 D4); **affordances render per the viewer's grant coverage (`write_regions`), never a role enum** — the UI twin of ADR-405's no-species-law. Reads stay universal; FE gating is legibility, the server gate is enforcement. | FE home: `web/lib/workspace/viewer.ts` (roster + memberships module-cached; `useViewerGrant`) + `GrantGate`. A fresh member lands on the same `/home`; there is no member onboarding fork, ever. |
| **Ambient commons context** *(canonical, ADR-412 D6)* | The which-workspace read + the compact who's-here roster read (**membership, never presence** — the ADR-373 no-realtime rejection stands), **homed in the UserMenu** (operator ruling 2026-07-07: the menu, not fixed top-bar chrome — a brief top-bar chip was tried and reverted same day). Depth lives at Workspace Settings → Workspace Members. | FE: `UserMenu` (one home for account + workspace context); both reads off the module-cached viewer-layer fetches (`lib/workspace/viewer`). |

## Three Altitudes, Three Chromes (ADR-408 D2 + ADR-412)

The three kinds of AI in a workspace, each with exactly **one chrome home** — *placement is the pedagogy* (same chrome must never imply same kind; no labeling fixes what placement asserts).

The chrome-home column stays correct; two cells are re-read: (row 2) the **base agents `Sonnet/Scout/Critic/Designer` are the member-hands cluster and DO appear on `/agents`** as addressable colleagues, not only in `/chat`; (row 3) `/agents` is therefore **not "Altitude 3 only"** — it is the addressable-colleague roster spanning member-hands (base + named instances) and, when hired, judgment agents. Row 1 is retired (ADR-632). See [LAYER-MAPPING.md](LAYER-MAPPING.md) (fact-vector, 2026-07-18).

| Cluster | Kind | Chrome home | Never appears as |
|---|---|---|---|
| management | **Retired (ADR-632)** — the steward that once held this row is deleted; substrate integrity is machinery + gates now | none | — |
| member-hands | **Base agents + lanes + named instances** — the member's addressable colleagues (ADR-411/460), `member:` attribution | **`/chat`** (the engine workbench — ADR-558) **AND `/agents`** (the beings pane — ADR-600 D6: residents sectioned by desk; the offered roster is empty, honestly). The kernel four and the member-agent machinery (`based_on`) are DELETED (ADR-599); beings are Editor · Designer · Supervisor (ADR-602/603/610). | chips in the lane; the member is the principal |

## The Acts — Think · Make · Perceive (ADR-507, 2026-07-30; supersedes ADR-457's two-verb pipeline)

The service in one sentence: **a desk of acts — Think, Make, Perceive — over a commons that remembers.** Each act is a **medium**, and each hosts apps. **Neither list is closed** — that openness is the model, not a caveat (ADR-507 D1): a new **app** is a row under an existing act and needs no ADR; a new **act** needs one, and the bar is *a medium the existing acts do not cover* (never a feature, an output shape, or an engine).

Their media differ by the shape of the work: divergent work has no stable visual state so its medium is dialogue; convergent work does so its medium is the artifact (*words for exploring, hands for shaping, attention for what arrives*).

| Act | Medium | Apps today | What it is | Guard |
|---|---|---|---|---|
| **Think** | dialogue | `/chat` | Grounded, multi-engine dialogue over the authored commons — research, ideation, deciding; the member's-hands operations ride along as means. Its defining property: thinking **lands**, because every lane write is an attributed revision. | The floor-leverage test — every chat feature must exploit the floor (grounding · provenance · multi-engine); generic chat-parity is refused. | **Export** (contrast) | Not a reach act at all: bytes leave, attribution and revocability are lost — irreversible egress governed by *honesty* (the declared-omissions manifest, ADR-510), not authorization. ## The Six Dimensions (FOUNDATIONS Axiom 0)

Every mechanic in YARNNN occupies a cell in six orthogonal dimensions. These are the axiomatic vocabulary that governs every other term in this glossary. Each dimension answers one interrogative:

| Term | Interrogative | Decides | Canonical reference |
|---|---|---|---|
| **Substrate** | What | What persists between invocations | FOUNDATIONS Axiom 1 (filesystem) |
| **Identity** | Who | Which cognitive layer acts or authors | FOUNDATIONS Axiom 2 (four layers) |
| **Purpose** | Why | What intent drives the work | FOUNDATIONS Axiom 3 |
| **Trigger** | When | What invokes execution (periodic / reactive / addressed) | FOUNDATIONS Axiom 4 |
| **Mechanism** | How | By what means — spectrum from deterministic code to LLM judgment | FOUNDATIONS Axiom 5 |
| **Channel** | Where | To what location or surface output is addressed | FOUNDATIONS Axiom 6 |

**Usage rule:** when writing an ADR, a design doc, or a code comment that introduces a new mechanic, state explicitly which dimension(s) it occupies. A mechanic that spans dimensions without explicit justification is a cross-cut — cross-cuts are legitimate only when argued for (e.g., compose substrate deliberately couples Mechanism + Channel per ADR-148). See FOUNDATIONS v6.0 Derived Principle 1 (Dimensional purity).

### Trigger-dimension vocabulary (the wake / cadence / pace cluster)

The five terms below are the Trigger-dimension (Axiom 4) + autonomy (Axiom 5) cluster. They are easy to conflate; keep them distinct. **Canonical synthesis with full mechanics, lifecycle, and substrate map: [`cadence-and-wakes.md`](previous_versions/cadence-and-wakes.md).**

|---|---|---|

| **Cadence** | *Retired (ADR-603/632).* Was the composed shape of the seat's self-authored wakes. A standing declaration carries its own schedule; nothing composes over them. | Trigger — historical |
| **Pace** ⚠ **RETIRED → Budget** ([ADR-327](../adr/ADR-327-budget-and-the-self-improving-loop.md), Implemented 2026-06-08) | Historical term. ## Vocabulary note: Agents, Orchestration, and Persona (ADR-216 2026-04-24)

**Standing declaration** *(canonical, ADR-603 D1; recut by ADR-639 D3, 2026-09-04)* — a **target** (the kept file) + a **contract** (`CONTRACT.md` — what "true" means for it) + **sources** + a **schedule** + the **app** whose standing executor does the work, producing an attributed revision or an honest no-op. Lives beside the thing it keeps: `{folder}/_standing.yaml` (machine config; keys `target · app · schedule · sources · shape · paused · paused_until` — `DECLARATION_KEYS` in `services/standing_work.py` IS the parser's whitelist) + `CONTRACT.md` (prose, never machine-parsed). **The contract is the load-bearing part**: without it, *"did this run do its job?"* has no answer — which is why a **recurrence** (a schedule + a prompt, no contract) could only ever be a scheduled interruption, and why ADR-603 D5 retired rather than absorbed it. ⭐**A declaration names the APP, never an agent** (ADR-603 D2), and since ADR-639 the app **derives from the target's type when absent** (prose → `text`; a structured target runs mechanically and needs no executor) — explicit wins; an agent slug in `app` is refused as `app_invalid`. The executor is `app → standing_executor_for_app → agents_registry` (Editor for a kept prose file today). ⚠️ A declaration is authority over **work**, never over an **agent** (ADR-596 D2): no key names an agent and none may. Discovered by the tick, indexed on `tasks` as `kind='standing'`, run through the ONE drain loop (`services/scheduling.py::drain_due`, shared with capture), bounded by the pool before the fetch (ADR-618). See **Standing work**.

**Supervisor** *(historical — retired by ADR-639, 2026-09-04; the **Strings** app and the **Keeper** agent with it)* — ADR-603 D3's resident "whose material is declarations", given the strings pane by ADR-604 and the pane WHOLE by ADR-610. The audit found it was a posture string with no mechanics (no code branched on its slug; the receipt face was a literal beside `system:strings`), and ADR-610's own rule — *a being is someone a member MEETS; work nobody watches is a daemon* — retired it once declaring became craft any resident holds (`declaring-standing-work`) and the pane was gone: it was what Keeper had been, a name on a receipt. The row left the register; `HISTORICAL_AGENT_NAMES` resolves the slug on the cast and transcript rows it signed (never rewritten); the strings lanes re-stamped `app: text` (migration 252) re-seat as Editor at read (ADR-614). Its two arguments (ADR-603 D3) are met elsewhere: *orchestration wants a conversation* → any pane, under the skill; *familiarity* → a product claim the operator ruled on. Do not reintroduce an agent for standing work.

**Standing work** *(canonical, ADR-639, 2026-09-04)* — **a kernel lane, not an app.** What a member declares lives beside the kept file (the **standing declaration**); what runs it is a daemon (`services/standing_work.py` on the scheduler tick, through the one drain loop); how it is done is a **skill** (`keeping-a-file-current`, composed into the run by binding; `declaring-standing-work`, offered in every lane's index); who does it **derives** from what the file is (target type → app → that app's standing executor). Nothing in that sentence is an agent. The run's system prompt is `lane_runner.build_standing_frame` — the lane frame minus what a toolless run and an absent principal make false (no tools, reach, cast, focus, register clause or skills index) plus the kernel JOB (the output contract: the full file or exactly `NO_CHANGE`) and the craft skill's body. Attribution `system:standing` (historical `system:strings`), displayed **Standing work** — machinery, no face. The roster and its two direct switches (Run now · Pause) are the Notifications window's **Standing work** pane (`/api/standing`); `/strings` redirects there. Ledger rows `standing-sweep:` / `standing-write:` with `funnel_decision='standing'` (migration 251). Gate: `test_adr639_standing_work.py`.

**Strings** *(historical — ADR-569 → ADR-639)* — the app that first carried the maintained file (ADR-569, 2026-08-14: designation, `_string.yaml` + `CONTRACT.md`, the Keeper colleague, the desk), later Supervisor's pane (ADR-604/610). ADR-639 decomposed it: the mechanism survives whole as **Standing work**; the craft became two skills; the pane became a Notifications view; the app, its routes, its surface and its two agents are deleted. The name survives only on historical rows (`system:strings`, `string-*` ledger slugs, `funnel_decision='string'`), all display-resolved or read by a named legacy prefix, never rewritten. ADR-569 D1 (designation is the boundary), D3 (confinement + shape refusal) and D4 (execution rides the `tasks` index) are unchanged law.

**Agent** (recut by ADR-596, collapsed by ADR-600, 2026-08-24; **the one noun since ADR-631**, 2026-09-02) — **identity ⊕ character ⊕ engine, and nothing else.** Universally, for every species of principal. ADR-596 introduced *being* as a transitional noun to break four drifted senses of "agent"; the definition is what mattered, the code said `agent` throughout (the register, the home folder, the pane, the caller class, the attribution prefix), and ADR-631 retired the second word — see **Being (historical)**. **ONE register** (`agents_registry.AGENTS`) — ADR-600 deleted the `KERNEL_AGENTS`/`KERNEL_POSTURES`/`APP_RESIDENTS` split: three dicts with identical row shapes and one shared resolution namespace were a *visibility flag modelled as three containers*, and an agent that changes container when a property changes broke two planners silently, emptied a pricing ratchet to zero rows, and let the cast door admit agents the roster refused. **Every question about an agent is a FIELD on it**: `offered` answers *may a member invite this agent into a conversation* — `False` means its home is an app (met in that app's pane), `True` a colleague (nobody today, ADR-599 D1); `kernel` (ADR-601 D2) answers *did yarnnn author this agent* — descriptive **provenance, never authority**, and deliberately not spelled `editable` (the two coincide today but may diverge; editability is a policy over provenance, enforced at `assert_editable`). **Capability is on NEITHER — it belongs to the APP** (ADR-601 D1): a bound lane's job overlay is selected by `app` and DERIVED from the app's own registries (measured 86.7% of a Slides frame vs the character's 2.4%), so an agent's prompt weight is constant in the number of apps it serves and **one agent may serve many apps** (ADR-597 D2's injectivity retired; an app still pins exactly ONE resident, ADR-467 D1). **ONE served relation** (ADR-631): the lanes envelope carries every agent under `agents` with `apps` — a list of the apps it works in as each app's own identity (slug · title · icon_key · route) — replacing the `beings` key and its `homes` / `home_titles` / `desks` triple, and the always-empty `offered`-only `agents` roster that sat beside it. Live pairing (ADR-602/627/639): **Editor** → slides · text (authoring — decks and prose) · **Designer** → images (generation — the metered pipeline) · **Blogger** → blogger (ADR-627). **Supervisor → strings is retired** (ADR-639: standing work is a kernel lane; the executor of a kept prose file DERIVES to Editor through the `standing_executor` seam ADR-604 opened, which survives as an undeclared field on every app). An agent's appearance on the /agents pane is DERIVED from whether any app it serves is PROMOTED (`is_promoted`, ADR-602 D3), never a column on the row: promoting the app promotes its voice in one edit. `offered` is **reach, never authority**. An agent row carries identity facts only — **never authority, never reach, never a clock** (the ADR-460 D3.a cliff, restated positively: *authority attaches to relations and declarations, never to agents; it is granted, audited, revocable, and enforced by kernel gates*). The four facts of an empowered agent house separately (ADR-596 D2): **identity** → the agent's substrate folder; **reach** → `principal_grants` (kernel-held; ADR-405: a grant, never a species rule); **clock** → declarations (`_string.yaml`, hooks), resolved against the **workspace home timezone**; **judgment** → gated policy files + the machinery-written dossier (track record) grants widen against. Distinct from **Machinery** — kernel code executing unconditionally (`system:` attribution), no dossier, no grants; it may wear a character's costume for display (the strings writer) — and from a **connected principal** (an MCP / foreign-LLM principal: it attributes as itself under a grant, but yarnnn runs no character or engine for it; the pre-ADR-415 Channels pane called these "External Agents", a collision ADR-631 retires). **An agent carries no RECORD of its own** (ADR-640): no surface, payload, ledger column or derived view presents work, output, cost or history attributed to an agent. The attribution rule records the hands and the tool (`member:{id} via {model}` — ADR-408, preserved by ADR-460) because an agent is a character the member's hands wear; a dossier predicates agency of a costume. The only agent-shaped join (`execution_events.session_id` → a lane's `agent` stamp) is lossy AND *historically correct in the way that makes present-tense aggregation false* — 25 live lanes truthfully read `app='text' agent='designer'` because ADR-602 moved Text to Editor after they happened, so any total over them states August as though it were now. What IS permitted, read-only and derived: the **craft** (skills whose `metadata.apps` meet this agent's apps) and the **tending** (declarations whose `resolve_executor` is this agent) — relations the kernel already computes, never settable, since a door that ASSIGNS a skill, a file or reach to an agent is authority on an agent. *An agent is met, not audited.* *Historical sense*: "Agent = persona-bearing judgment entity" (ADR-216 era) described the omniscient-steward conception, since retracted; the steward's stack is deleted (ADR-632).

**Resident** (ADR-598, recut by ADR-600/601) — an agent whose home is an APP: it speaks for that app, met in its pane, never invited (`offered: False`). An app pins exactly ONE resident (ADR-467 D1); an agent may serve MANY apps (ADR-601 D1 — capability lives at the app, so a second app costs an agent nothing). Derived at read time from `register_app(resident=…)`, never stored on a lane. **ADR-604 D2 splits an app's two roles**: `resident` is the VOICE (the bound-lane conversation) and `standing_executor` — declared only where they diverge — is who executes the app's unattended runs and whose face the receipts wear. Today: Editor → slides · text; Designer → images; Blogger → blogger (Supervisor → strings retired by ADR-639; no app declares a `standing_executor` today, so every one derives its resident — and a standing declaration on a kept prose file derives Editor through it).

**Colleague** (ADR-598's other half) — an agent a member can INVITE into a conversation (`offered: True`). The distinction from resident is the answer to "who am I talking to": a resident comes with the app, a colleague is picked. The offered roster is EMPTY today (ADR-599 D1) — honestly, as an observable fact on the rows (ADR-600 D2), not as a property of a deleted namespace.

**Steward** *(historical — retired by ADR-632, 2026-09-02; also **Freddie**, **Reviewer**, the **review seat**, the **occupant**, **wake**)* — the systemic, persona-bearing agent that once held every workspace's judgment: its own prompt layer (`agents/freddie_agent.py`), model table, wake sources → evaluation funnel → wake queue → drainer, review-seat rotation, kernel mirrors, chat drawer and mascot. ADR-596 D3 ratified its dissolution in five phases; ADR-632 executed them in one arc after an audit found it dormant (1 wake since 1 Aug) but still wired to the scheduler tick. Nothing wakes on its own initiative now: an **attended** turn is a member's message in a lane, an **unattended** run is a **standing declaration**'s schedule (ADR-603). The verdict-giver on a proposal is the operator until ADR-596 D3 phase (d) lands review as a grant + policy declaration. The `freddie:` attribution prefix survives on historical revisions, display-resolved, never rewritten. The billing **seat** (ADR-445) is a different word and keeps it. The seat canon is archived under `docs/architecture/previous_versions/`.

**Being** *(historical — retired by ADR-631, 2026-09-02)* — ADR-596's transitional noun for what is now simply an **Agent** (identity ⊕ character ⊕ engine). It was introduced to break four drifted senses of "agent" while the taxonomy settled; once the definition and the housing rule were gated, the second word only cost a translation at every code/canon boundary (code said `agent` throughout). Ratified ADRs keep the word as a record of their time; live canon, code, and surfaces say **agent**.

**Pane** *(canonical, ADR-522/606, named as the one surface noun by ADR-631)* — the surface where an app is used: the bound lane, the artifact or maintained file, the activity rail and the pane housing, on the authoring width ladder. **App** is the kernel row (`register_app`), **pane** is where a member uses it, **resident** is the agent met there. The lane frame's job overlay is the app's *pane posture* (`studio_pane_posture` · `text_pane_posture` · `_strings_pane_posture`), composed at ONE kernel site (ADR-606). *Desk* (historical) named the same surface, and `homes` / `desks` named the same agent↔app relation the envelope now serves once as `apps` — three words for one thing, retired together.

**Skill** *(canonical, ADR-630, 2026-09-02)* — a how-to file for a kind of WORK: a folder holding `SKILL.md` (frontmatter `name` + `description`, optional `metadata.target`; body under 500 lines — the Agent Skills convention, a named ADR-254 exception). It teaches CRAFT and never grammar (the pane posture derives that from the app's registries), never the PARTICIPANT contract (the kernel constants — ADR-533), never reach (the gates; prose is not permission — ADR-464 §3), and **never names an agent** (a skill is about work, not identity — ADR-596 D2). ⭐⭐⭐**Which skills earn their bytes was MEASURED 2026-09-04** (A/B, index composed vs suppressed): a skill pays when it carries a right answer **the model has no prior for** — one of *this workspace's own shapes* (`_design.yaml`, an artboard's `data-z`, a deck's numbers in a sibling CSV, a spec's seven sections). Skills teaching craft a frontier model already holds (`reviewing-drafts`, `writing-updates`, `comparing-options`, `summarizing-sources`) measure flat. **The paying half fails SILENTLY** — `design_systems.py` discovers a system BY its manifest, so a folder without one is invisible while looking like plausible CSS — which is why **a skill is never pruned on a quality score**: the ones worth keeping are the ones whose absence a reader cannot see. A null is an argument about the current engine, not the file. Two homes, one shape: yarnnn's skills are CODE (`api/services/skills/{slug}/SKILL.md`) **mirrored** into every workspace at `system/skills/{slug}/SKILL.md` as `system:kernel-skills` revisions (read-only by topology; manifest-cheap; landed on first use, never seeded at birth); a workspace's own live at `skills/{name}/SKILL.md` as ordinary substrate (attributed, versioned, forkable — DuplicateFile records the origin). **Discovery is the description**: every lane's frame carries one index line per skill (kernel from code, member from one bounded query, byte-ceilinged), and the body loads on demand through ReadFile (DP22 — the frame carries the door, never the room). Three doors, one content: the agent reads it when the index matches; the lane binding `skill` + `derive_source` opens one deliberately (the ADR-450 D3 binding, renamed from `derive_recipe`; "Learn from" is still the member's verb); the ADR-579 D8 click seeds the same binding. Version control is the ledger — no semver, no lockfile, no per-workspace enable list. *Recipe* (ADR-450) is the historical name for a kernel skill; the registry is the folder.

**Feed surface** *(retired — ADR-370 folded it into Context; ADR-632 D4 closed the `/feed` doors)*: the seat-era primary timeline. The workspace timeline lives at Notifications → Activity (ADR-410); the boundary lens at Reach (ADR-642).

**Channels (surface)** (canonized by ADR-370 as "Context", 2026-06-25; **renamed `context` → `channels` by ADR-385, 2026-06-29** — "context" was ambiguous with the filesystem [Files surface] and the `operation/context/` substrate namespace): the operation's **perception + principal** surface — the edge where the workspace meets the outside world. A `SettingsPaneShell` split-nav, two groups: **CHANNELS** — what crosses the edge: **Connections** (platform data-feeds — status·coverage·freshness), **Sources** (standing web/RSS watches, ADR-335/336), **External Agents** (retired wording — ADR-631 says **connected principals**; MCP / external-LLM principals — a *filtered view* of the `principal_grants` member roster, `role ∈ {foreign-llm, a2a, platform}`; ADR-373 + ADR-385 D3, one substrate two views per DP29). **ACTIVITY** — the running record of crossings: **Flow** (the complete narrative — FeedSurface; the *default* landing pane), **In** (inbound crossings — FeedSurface filtered by `isInbound`), **Out** (the operator-addressing dispatch ledger via `GET /api/emissions`, read-only — a *distinct* data source, not a narrative filter, which is why In/Out/Flow stay distinct nav items not filter chips). A *composition* (one surface ↔ one act, ADR-340 DP29), not a mirror. URL `/channels` (`/context` + `/feed` are ADR-308 redirect stubs). Two orthogonal planes co-locate in CHANNELS without overlap: Connections = *what feeds* the operation (`platform_connections`); External Agents = *who can write* the commons (`principal_grants`). Narrative redundancy with Notifications → Activity is deliberate tiered redundancy (ADR-367 D3 macOS principle). **Disambiguation**: the route slug is unrelated to the retired `context/` substrate root (ADR-320 → `operation/`) or "context domains" (ADR-151 fiction).

**YARNNN** is the product brand and the voice of the orchestration entry mode on the feed surface. In the cockpit, the conversational surface entity is called the **System Agent** (see below). On the feed, the system speaks as "YARNNN" — the brand and the surface entry mode share a name. YARNNN (reclassified by ADR-216): the **orchestration feed surface entry mode**, *not* a persona-bearing Agent. Platform-fixed voice (no workspace-authored IDENTITY file), no standing intent, no fiduciary weight. Retains an `agents` table row with `role='thinking_partner'` as implementation substrate for session state; the row is implementation, the classification is architectural.

**System Agent** *(retired — dissolved as a cockpit entity by ADR-272, 2026-05-14; the steward that briefly refilled the role is deleted, ADR-632)*: machinery is attributed `system:{actor}` and has no entity of its own (FOUNDATIONS Axiom 2).

**Orchestration** in YARNNN means production machinery: task pipeline, dispatch routing, capability bundles, back-office scheduling, **and the YARNNN feed surface**. Orchestration has no standing intent, no fiduciary relationship, no accumulated identity of its own. It is stateless computation (or platform-fixed-voice conversation) that runs *under* Agents. **Orchestration is never persona-bearing.** Performance-fungible (swap one orchestrator for another and work executes the same way; swap one persona-bearing Agent for another and outcomes diverge — that divergence is what persona is).

**Persona** *(retired — ADR-624 deleted `IDENTITY.md` from the agent's home; **character** is the live word, ADR-596)*: an agent's character — posture, register, craft — ships with the agent from the one register (ADR-600); a member may replace its face (ADR-641 am.2), but the character is not a per-workspace file.

The three classes in one sentence: *Agents hold intent and render judgment through their authored persona. Orchestration runs under them, bundles capabilities, dispatches production, and surfaces the operator-facing chat. Persona is the operator-authored character that distinguishes one Agent instance from another.*

Industry's "agent" vocabulary (LLM + tools + loop + memory = "agent") maps most closely to YARNNN's **production roles** (Researcher, Analyst, Writer, etc.) — packaged production capabilities, not Agents. Industry has consolidated the word around the wrong referent. **YARNNN does not follow.** The word belongs to judgment-bearing entities and is used accordingly, in canon, code, and ADRs going forward.

External product vocabulary happens to align naturally: the "Agents" the operator sees on `/agents` ARE Agents in the sharp sense (user-authored domain workers hold operator-authored intent, represent the operator, accumulate). No external vocabulary shift required.

Retired terms (see Retired-terms table):
- "Specialist" as an entity — retired for the orchestration-role concept. Use "production role" instead.
- "Platform Bot" as an entity — retired. Use "platform integration" instead. (ADR-207 P4a already dissolved them as agent class.)

## Enforcement rule

1. **New ADRs must use glossary terms.** If a concept requires a word the glossary doesn't have, add it here first, then use it in the ADR.
2. **Retired terms cannot appear in active docs or code comments.** They may persist as internal DB slugs (e.g., the `thinking_partner` role value) where migration cost exceeds reader benefit — those exceptions are listed in the Exceptions table.
3. **Renames propagate in a single commit.** When a term is added, changed, or retired, every active doc and every prompt must move in the same PR. No staged rollouts.
4. **User-facing strings must pass the instinct test.** A non-technical user reads the term and immediately knows what it means. If a term needs a definition before it's useful, it's the wrong term.

## Authoring grains — per medium (ADR-544 paged · ADR-546 flow)

The authoring apps have **two** grain vocabularies, one per medium, and that is a
decision rather than an inconsistency: what "depth" means differs. On a **paged**
medium (deck · web — Studio) depth is *containment*; on **flow** (document —
Docs) depth is *the rung*. The machinery is shared (one write door, one normalize
seam, one selection algebra); the **law** is per-medium (ADR-546 §2.3, which
refused a hard app fork with the measurement).

> ⚠️ **"Rung" is overloaded — check which sense.** The *activation ladder's*
> **Rung 0·1·2** (ADR-380, above) is about workspace activation and has nothing to
> do with authoring. The authoring **Rung** below is a document's depth grain.
> Neither predates the other in the codebase; both names were operator-chosen in
> their own domain. Disambiguate by context: activation rungs are numbered, the
> authoring rung is a grain in `Document → Rung → Block → Range`.

| Term | Definition | Notes |
|---|---|---|
| **Slide / Layout / Area / Block** *(paged; ADR-544 D0)* | The four grains of a **paged** medium. **Slide** = the frame, one coordinate space. **Layout** = the named arrangement it wears ("Two column"). **Area** = a region of the layout, typed by a **role** from a closed set (`heading \| body \| media \| aside`) with a `place` for same-role siblings. **Block** = an object in an Area. **Containment is total**: no block is a direct child of a slide, and a block's *position IS its Area + its order within it* (D3 — `x/y/z` retired for decks, surviving on the `artboard` grain for IMAGES). | Three of four words are operator-chosen. **"Section" was REFUSED** (already the span between headings in Docs, plus a standing `<section>`-wrapper refusal, plus it is the slide's own HTML tag); **"Object" refused** (already a selection *tier*). Typing Areas by content (title/subtitle/body) was refused — it duplicates what the block declares and breaks on "multiple subtitles". See [ADR-544](../adr/ADR-544-the-containment-law-slide-layout-area-block.md). |
| **Document / Rung / Block / Range** *(flow; ADR-546 D0)* | The four grains of a **document**. **Document** = the file, one continuous writing surface, no coordinate space. **Rung** = a step of subordination (see below). **Block** = a paragraph, list, quote, table, figure — **the addressing floor**. **Range** = what the member has selected, a span that may cross blocks. **There is no container grain and no page grain, by derivation** — a capture surface that asks "where on the page" has stopped being a capture surface (`docs.py`). | The Docs analogue of an **Area is nothing**, deliberately. `Slide`, `Layout`, `Area`, `slot`, `col`, `container`, `page` and every raw `data-block` value are forbidden in operator-facing text on flow — the symmetric twin of ADR-544 D4's rule for decks (ADR-546 D5/F1; ADR-544 F2 had been one-directional, so `structureLabels.ts` returned `Slide` for a `<section>` and `Group` as its fallback on a ladder flow calls ungated). |
| **Rung** *(authoring, flow; ADR-546 D1)* | Depth on a document: **one concept with two spellings** — the **heading rung** (`h1/h2/h3`, subordinating everything to the next heading of equal-or-shallower rung) and the **nesting rung** (a list item's depth, a prose block's step in from the measure). Declared ONCE as `FLOW_RUNGS`; the served `indent` token's values and the kernel's list-nesting CSS are **generated from it**. Intake clamps to the set (migration-by-use, never a sweep). | At the 2026-08-10 audit depth was declared **three** times with wildly different readership — six consumers, one, and **none** — while agreeing by luck on the number 3. The third (`ul ul ul` in the kernel CSS) had no reader at all, which is why **Tab could author a hierarchy nothing could name**. **Tab is the rung gesture and means one thing**: nest/un-nest in a list, step the prose rung in prose (the literal-tab-character branch is DELETED — ADR-546 D4/§4.1). |
| **A rung is a PROPERTY, not a grain** *(ADR-546 D2)* | A rung belongs to a block; it is never a thing that *holds* blocks. **An `<li>` never carries `data-block-id`** — a list is one block, and its interior depth is a rung it carries. `normalizeStructure` is untouched. | The addressable-list-item alternative is Notion's model and would **move the attribution floor**, which ADR-528 §2 measured as whole-FILE. Refused for now, with the reopening evidence named in ADR-546 §5. |
| **Span shape** *(ADR-546 D3)* | A range's structural description: a selection covering a heading and the blocks beneath it is a **subtree**, not N peers. Derived once by `spanShapeOf` (`selection.ts`), which also owns the sentence (`spanLabel`) — beside `withdrawalNotice`, for the same reason. | Before this, `formatSegments` was flat by construction ("Top-level blocks only"), so the rung relation the outline already computed was discarded at the one place a span's subjects are derived — and the pane could only count ("7 blocks selected"). A span that does not open on its shallowest block reports **no lead** rather than guessing one. |

| **Draft** | YARNNN | a Team | Per-task. Iterative. Re-drafted every task cycle from the Specialist palette. |
| **Evolve** | Feedback loop | an Agent or a Specialist | Continuous. Agents evolve domain identity; Specialists evolve role-scoped stylistic memory. |
| **Scaffold** | System | a workspace | Once, at signup. Reserved for workspace-level setup. Never used for agent creation. |

**Asymmetry is deliberate.** The user *creates* an Agent (generic, neutral, universally understood). YARNNN *drafts* a Team (precise about the iterative per-task selection nature of the act). Collapsing these to a single verb loses information.

## Exceptions

Cases where a retired term persists by necessity, and the migration cost exceeds the reader benefit.

**The governing rule** (ratified 2026-07-08 — [naming-drift policy](../analysis/naming-drift-policy-2026-07-08.md); this table is its instance set): when a concept is renamed, the new name propagates **down from canon only as far as the render layer by default**. Below the render boundary, internal names are **stable**:

- **Render strings** (layer e) — RENAME immediately (ADR-410 D4, mandatory).
- **API response fields** (layer d) — **BOUNDARY-MAP**: serialize the canon name over the unchanged internal source at a single adapter, so the external contract speaks canon while the DB/enum/identifier stays stable (e.g. the proposals `agent_identity`/`agent_reasoning` serializer over the `reviewer_*` columns, `routes/proposals.py::serialize_proposal`).
- **Python/TS identifiers** (layer c) — KEEP (relabel-keep-slug); rename only opportunistically when already editing the file, never as standalone churn.
- **Enum/slug values** (layer b) — KEEP forever (immutable ADR-209 data; a rename is a data-format break).
- **DB columns** (layer a) — KEEP, and migrate ONLY when the column is *also* a live API field the FE reads AND the boundary-map is not viable AND the rename is durable (all three; else boundary-map the field, keep the column).

This is what makes the exceptions table *bounded*: the reader-facing gap closes at the API boundary-map, so the table records "internal X → canon Y at adapter Z" rather than an ever-growing pile of one-offs a new developer must memorize.

| Location | Term that persists | Why |
|----------|-------------------|-----|
| `action_proposals.reviewer_identity` / `reviewer_reasoning` DB columns | `reviewer_` (columns) | Internal attribution slugs (`human:{uid}`, `ai:freddie-sonnet-v8`), never rendered raw. Renaming the columns would cascade through every writer/reader + the ground-truth join + the tenure probes for zero data-shape benefit (ADR-414 §8 amendment). The **API contract** speaks canon: `routes/proposals.py::serialize_proposal` maps them to `agent_identity`/`agent_reasoning` (the boundary-map — the FE reads the canon aliases). Layer-(a)-kept, layer-(d)-mapped. |
| `authored_by` string prefix `yarnnn:` in revision records | Unchanged | Revision-chain data format. Historical revisions carry the prefix. Immutable per ADR-209. |
| `/workspace/persona/` (seat path) | `persona/` | Historical: the seat path `persona/` (ADR-320) and its `freddie:` occupant prefix survive only on legacy workspaces and historical revisions, display-resolved (ADR-632 §3). No live code reads `persona/` as a home. |
| `authored_by` string prefix `specialist:<role>` | Unchanged | Revision-chain data format. Historical revisions carry the prefix. ADR-209 Authored Substrate is stable across the LAYER-MAPPING flip — only the human-readable taxonomy changed, not the data format. |
| Historical ADRs (140, 164, 176, 186, 241, 247, etc.) | References to "TP", "Thinking Partner", "Specialist" (entity term), "Platform Bot", "meta-cognitive" (as label) | ADRs are historical artifacts. They are not rewritten when terms change; they stand as dated records of the decisions in force at their time. New ADRs supersede them; the supersession is the record. |

All other appearances of retired terms — prompts, active architecture docs, new code, UI strings, marketing — must use replacements.
